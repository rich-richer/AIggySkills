# 故障模式与判定

取料最常见的失败是**"看起来成功了"**。本文件给出识别方法与降级规则。

## 一级信号：三个必查项

每次取料后必须核对：

| 检查 | 方法 | 失败判据 |
|---|---|---|
| HTTP 状态 | 日志里的 `Fetched (200)` | 403 / 404 / 429 / 503 |
| 输出体积 | `wc -c` | 0 字节，或明显小于同类页面 |
| 内容特征 | `grep` 目标关键词 | 只有导航、登录、页脚 |

> `scrapling` 的退出码恒为 0，**不是成败依据**。被 Cloudflare 挡掉时依然打印
> "Content successfully saved"，输出 0 字节。

## 常见故障

### 1. 登录墙（伪装成 200）

**表现**：200 + 几十 KB，但内容全是「登录后推荐更懂你的笔记」「扫码登录」「用户协议」，以及大量 base64 占位图。

**识别**：`grep -c "登录\|扫码\|用户协议\|隐私政策"` 命中多次，且 `grep` 不到目标正文关键词。

**处理**：不要试图绕过。改用 `ego` 浏览器 + 让用户登录。若用户不登录，标记 `integrity: fail` 并说明。

### 2. 付费墙 / 部分可见

**表现**：正文前两段完整，后面突然出现「继续阅读」「订阅解锁」。

**处理**：`coverage` 写清可见范围（如「仅前 3 段」），`integrity: degraded`。禁止用标题推测后文。

### 3. 0 字节 / 选择器未命中

**表现**：`-s "xxx"` 输出 0 字节。

**处理**：先抓一次 `.html` 看真实标签，或换更稳的选择器。0 字节 ≠ 工具坏了 ≠ 页面没内容。

### 4. 反爬 403

**表现**：状态 403，体积 0。

**处理**：换 `fetch --solve-cloudflare`，加 `--impersonate chrome`，或加 referer。连续两次失败 → `fail`。

### 5. ASR 同音错字

**表现**：专有名词、人名、专业术语成片错误（蒸馏→征流、Skill→Skew/Scale、复用→附用、验收→键售）。

**识别**：同一概念在转写里出现多种写法；出现明显不成词的组合。

**处理**：
- 抽 6–20 张关键帧，读画面上的标题/术语表做对照（PPT 类视频尤其有效）。
- 术语表以**画面文字为准**，不是转写。
- `defects` 里写明：「转写含同音错字，已用画面校正 N 处」。

### 6. 扫描件伪装成 PDF

**表现**：`pdftotext` 输出极少字符（字符数/页数 < 100），或整页空白。

**处理**：转图 OCR。中文需 `chi_sim`；语言包缺失时 `read_image` 逐页，并在 `coverage` 写明页数。

### 7. 视频无音轨 / 静音

**表现**：`ffprobe` 无 `codec_type=audio`。

**处理**：只能走画面（抽帧 + OCR）。明确告诉用户「无法得到口播内容」，不要编。

### 8. 时间戳漂移 / 跳段

**表现**：SRT 中时间不连续，或段数远低于时长（< 0.3 段/秒）。

**处理**：可能音频有丢包。重抽音频再转；仍不连续则标注 `degraded`。

### 9. 编码 / 乱码

**表现**：中文变成 `æ–‡ç«` 一类。

**处理**：`iconv -f utf-8 -t utf-8 -c`、或 `file -I` 查编码；PDF 用 `-enc UTF-8`。

## integrity 分级

| 级别 | 定义 | 下游可用性 |
|---|---|---|
| `pass` | 覆盖目标范围，无已知缺陷 | 可直接蒸馏 |
| `degraded` | 有明确缺口（登录墙部分可见、ASR 未校、抽页） | 可用，但下游必须知道缺口 |
| `fail` | 拿不到有效内容 | 不得进入下游 |

## 降级规则的底线

- `degraded` 必须写成**具体缺什么**，不能只写"部分"。
- `fail` 时**不要**输出推测性内容。给用户三条路：换来源 / 人工提供 / 放弃。
- 任何"根据标题/简介猜内容"的行为，等同于编造原料。
