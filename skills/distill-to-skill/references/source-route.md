# 资料型路线：从书 / 资料 / 视频里提炼方法

## 前置

已写出目标句与验收句（见 SKILL.md Phase 1）。没有就不要开始。

## 步骤

### 1. 先指出"这本书解决不了什么"

在提炼前，明确这份来源的类型，决定留什么：

| 类型 | 它真正提供的 | 应该留下 | 不应该做 |
|---|---|---|---|
| 方法类 | 可执行的操作与检查点 | 输入、判断、追问、输出、检查标准 | 只记观点 |
| 框架类 | 判断依据与评估维度 | 判断框架 + 适用范围 | 硬拆成步骤 |
| 视角类 | 换个角度看问题 | 观察角度 + 适用/失效场景 | 假装是流程 |

「不能假装一本书能解决所有问题」。类型判错，后面全错。

### 2. 输出五问清单

针对目标句，让模型（或你自己）回答：

1. **输入**：做这件事之前，必须先收集哪些信息？
2. **提问**：用什么问题能识别真实需求/真实问题？
3. **追问**：哪些回答必须继续追问？追问到什么程度？
4. **时机**：什么情况适合进入下一阶段（报价/交付/定稿）？什么情况必须退回？
5. **产出**：最后要形成什么结果？这份结果长什么样？

每一条都要能被**具体动作**验证，不能停在概念。

### 3. 强制标注出处

每条规则后面加标记：

- `[原文 p.xx / 章节]`：来源里明确写了
- `[原文隐含]`：来源没明说，但从原文结构可推出（说明推法）
- `[AI补充]`：为你的场景补的
- `[我的经验]`：你在真实任务里确认过

**判据**：如果一条规则你说不出它来自哪一段，它就是 `[AI补充]`，不得进入「必查」类。

### 4. 用真实样例空跑

- 拿一份**真实**的输入（真实客户记录 / 真实素材 / 真实数据），不要用构造的完美样例。
- 检查三件事：
  - 它能不能发现**缺失信息**？
  - 它提出的问题**有没有意义**（不是复述规则）？
  - 它会不会**把来源里没有的需求自己补出来**（脑补）？
- 「只会复述概念」= 不通过，回到步骤 2。

### 5. 定三段式输出

通过试跑后，整理成：

```
适用条件（什么时候用 / 什么时候不能用）
操作方法（步骤，每步带判断点）
检查标准（怎么算做对了，可逐条核对）
```

### 6. 交付前自检

- [ ] 每条规则有来源标记
- [ ] `[AI补充]` 全部落在「情境做法」或「示例」，没有进「必查」
- [ ] 示例至少一条来自真实案例，且已脱敏
- [ ] 写清了这份来源**不适用**的场景
- [ ] 验收标准是第三方能执行的，不是感觉描述

## 常见失败

| 失败 | 原因 | 修法 |
|---|---|---|
| 提炼出 20 条漂亮观点 | 目标句太泛 | 回去把目标句收窄 |
| 规则无法执行 | 停在概念层（"要共情"） | 改写成可观察动作（"复述客户原话再确认"） |
| 混入 AI 发明的方法 | 没有出处标注 | 补标注，无源降级 |
| 换场景就崩 | 把视角类资料当方法类 | 重做步骤 1 的类型判定 |
