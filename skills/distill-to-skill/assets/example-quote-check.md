# 报价前需求缺口检查（quote-gap-check）

把「倾听、共情、识别需求」变成可执行动作：读客户沟通记录 → 找缺失信息 → 给追问 → 判断能否报价。

## 何时使用

- 用：拿到一份客户沟通记录（微信、通话纪要、会议笔记），准备报价前。
- 用：新人销售提交报价申请，需要前置审核。
- 不用：客户已签合同、纯询价且不进入正式报价流程。

## 输入

1. 客户沟通记录原文（越完整越好）
2. 本次要报的产品/服务范围
3. 已知的客户预算信息（如果客户提过）

缺少沟通记录时，**不要**根据产品信息推测需求，直接要求补充。

## 判断规则

### 必查标准（每次都要过）

| # | 规则 | 证据 | 来源 |
|---|---|---|---|
| 1 | 每个已确认需求，必须能在记录里定位原话 | 引用记录行 | [原文] |
| 2 | 需求必须区分「客户说的」与「我方推断的」 | 标注推断项 | [原文] |
| 3 | 交付周期的每个承诺必须有依据（客户要求/产能/合同） | 依据出处 | [我的经验] |
| 4 | 预算信息缺失时，不得默认客户预算敏感或宽裕 | 记录中是否出现 | [我的经验] |

### 情境做法（按条件切换）

```
IF 客户明确给出预算上限
THEN 方案给出「满足上限」与「超上限但价值更高」两个版本，并说明削减了什么
ELSE 按价值定价，先讲结果与风险，再给价格区间
判断人：销售负责人
来源：[原文]
```

```
IF 客户提到"时间紧"但没有给具体日期
THEN 追问具体截止日期与不可延期的原因
ELSE 按标准交付周期报价
判断人：销售
来源：[我的经验]
```

### 不适用

- 当客户处于纯比价阶段（只要价格表、拒绝沟通需求）时，本规则不成立，应改为标准报价 + 客户资格判断。

## 操作步骤

1. **通读记录，列出客户明确说过的内容** → 每条带原话位置 → 产出：事实清单
2. **按五问找缺口**：输入信息是否足够？真实需求问到了吗？哪些回答需要追问？能否进入报价？要产出什么？
3. **为每个缺口写一句追问** → 追问必须具体、客户一句话能答
4. **判定报价就绪度** → 产出：可报价 / 需追问 / 不建议报价（附原因）

## 验收标准

- [ ] 每条「已确认需求」都能指到记录里的原话
- [ ] 每个缺口都配了一句可发出的追问
- [ ] 没有出现记录中不存在的客户需求（脑补检测）
- [ ] 结论明确给出三档之一，而不是"建议进一步沟通"

不合格的典型表现：输出「需求基本清晰，可以报价」，但列不出任何原话依据。

## 示例

### 示例：某客户预算上限 8 万

- 背景：客户提过「预算大概 8 万左右」，但没说是否含税、是否含实施。
- 用了规则：必查 #1（定位原话）、#4（预算信息不完整）、情境规则 1（给两版方案）。
- 结果：识别出 3 项缺口（含税、实施范围、验收方式），未直接报价。
- **换场景时怎么改**：8 万是单次信息，换客户重新确认预算区间；「给两版方案」是通用做法，保留。

## 出处与限制

- 来源：客户沟通方法论资料 + 实际报价审核经验
- 材料限制：记录不完整时（只有口头转述），缺口检测能力下降
- 已知边界：不适用于非标准品类的定制项目（需求本身需要多轮共创）
