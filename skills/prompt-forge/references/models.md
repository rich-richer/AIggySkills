# 模型适配（Model Adaptation）

**什么时候读这个文件**：提示词正文已经写好、准备贴进某个模型；要把一份现成提示词从 A 模型搬到 B 模型；或者用户抱怨"同一个提示词，换成别家就不好使了"。
**读完你会得到什么**：① 三家人模型的分叉对照表；② 按模型**类型**判断"该怎么写"的规则表；③ 换模型时要删什么、加什么的迁移清单；④ 同一个任务在三家模型上的三种写法（可直接对照抄）。

> 两个前提，先接受再往下读：
> 知识截止 **2026-11**。参数行为、报错条件、废弃节奏变化很快，**具体型号的行为以官方文档为准**（见文末链接），本文件只给判断框架。
> **不要写死型号，用判断规则**。交付物里写"如果你用的是推理模型，就……"，比写"GPT-6 里必须……"耐用得多——型号名半年就过时，判断规则不会。

## 1. 先分类，再动笔

改写入参之前，只回答一个问题：**这段提示词要跑在哪一类模型上？**

| 类型 | 怎么认（用户的原话常是） | 与之匹配的一句话写法 |
|---|---|---|
| 推理模型 | "o 系列""思考模式""reasoning""DeepThink" | 只给目标、成功标准、边界，别管过程；深度用 effort 档位调 |
| 通用聊天模型 | 没有思考开关的默认对话模型 | 明确指令 + 1–3 个示例 + 输出契约，动词写具体 |
| 图像/视频模型 | "文生图""图生视频""MJ""Veo""Seedance" | 主体 + 场景 + 动作 + 镜头 + 光线 + 风格 + 比例，一个提示词一个场景 |
| 小模型/本地模型 | "7B""本地跑""私有化部署""端侧" | 指令更短、示例更多、输出格式更死板，只做一件事 |

判不出来就问一句（`I-G4` 目标模型与使用形态）。用户答"不知道"，按通用聊天模型写，并在交付物里加一句迁移备注。

## 2. 三家分叉对照表（只查你正在用的那一列）

| 维度 | OpenAI GPT-6 系 | Anthropic Claude 5.x | Google Gemini 4 / 3.1 |
|---|---|---|---|
| few-shot | 推理模型**先零样本**，不够再补 1–2 个 | **建议给**，但要精简、典型、多样；官方反对穷举 edge case | **总是给**；示例够清楚时，甚至可以删掉一部分文字指令 |
| CoT 脚手架 | 明确反对写"一步步想" | 降级为 fallback：只在 thinking 关闭时补步骤 | 渐进式：先给通用指令，不够再补步骤 |
| temperature | 开了推理就**必须移除** temperature/top_p | 4.7+ 传非默认值直接 **400** | 4 / 3.6+ 直接**忽略**该参数 |
| prefill 控格式 | 无此机制 | 4.6+ 起**已废除**，传了报 400 | **仍在推荐**（response prefix） |
| 分区语法 | Markdown + XML 标签混用 | **XML 优先**（`<example>`、`<documents>`、`<rules>`） | Markdown / XML 皆可，但**分隔符写法必须前后一致** |
| 长度控制 | verbosity 参数 + 自然语言长度指令 | 只能靠 prompt（effort 不影响可见长度） | 一般性指令 + 格式约束 |
| 结构化输出 | 有 structured outputs，别用强措辞硬压格式 | 有 structured outputs，同理 | 有 structured outputs，同理 |

数据来源见 `./sources.md`。表里 "4.6+ / 4.7+ / 3.6+" 的版本门槛来自二手摘要，**上线前用一次最小请求实测**：故意传一个非默认 temperature 或 prefill，看是静默忽略还是 400 报错——30 秒就能验证你手上这个版本属于哪一列。

## 3. 判断规则表（比对照表更耐用）

| 该给什么 | 不要给什么 | 参数怎么设 | 长度怎么控 |
|---|---|---|---|
| **推理模型**：目标 + 成功标准 + 边界 + 交付格式；允许一句"想清楚再答" | "let's think step by step""先列出你的思考过程""第一步…第二步…" | 用 effort / reasoning 档位（低/中/高）代替提示词里的"请深入思考" | 一句具体长度指令（"5 条，每条 ≤25 字"） |

> **"想清楚再答"与"一步步思考"的界线**（这条边界文件里必须写死，否则执行时会摇摆）：
> - ✅ 可以说：`想清楚再答`、`答之前先确认有没有信息缺口`、`先判断这是哪一类问题`——这是**给标准**，不占输出位置。
> - ❌ 不要说：`第一步…第二步…第三步…`、`先输出你的思考过程`、`把推理链写进回答`——这是**给步骤/要过程**，对内置思考的模型是噪音，还会挤占输出。
> - 判据一句话：**"你让它达到什么状态"可以写，"它该怎么一步步走到那个状态"不要写。**
| **通用聊天模型**：明确动词指令 + 1–3 个示例 + 输出契约（字段/顺序/单位） | "优化一下""写得好一点""专业一些" | 输出要稳定就降 temperature（不在推理模式时） | 段落数 + 每段字数上限 |
| **图像/视频模型**：主体、场景、动作、镜头、光线、风格、比例；负面词写成**正向描述** | 否定句（"不要墙"→写"墙面干净"）、引号（会被渲染成画面文字）、一条提示词塞多个场景 | 比例/种子/时长写在参数里而不是正文里 | 一个提示词一个场景；短视频一镜到底 |
| **小模型**：单任务 + 3–5 个示例 + 死板格式（"只输出 JSON，不要解释"） | 多任务混写、开放式创作要求、长链路推理 | 温度调低，关闭发散 | 硬性字符/条数上限 |

## 4. 填好的示例：同一任务的三种写法

任务：把华东区 2026 Q3 的销售数据，写成给总经理的 5 条汇报要点。素材有：季度营收 1.82 亿（同比 +9%）、毛利率 31.4%（-1.8pt）、大客户流失 2 家、新签 3 家行业客户、库存周转 58 天（+6 天）。

**A. 推理模型（GPT-6 系）**——只给目标和边界，不排步骤：

```
你是华东区销售负责人，向总经理做 Q3 书面汇报。

素材：{{粘贴 data.md 全文}}。

目标：从素材里找出总经理最该在 30 秒内知道的 5 件事，写成 5 条要点。
成功标准：① 每条 ≤40 字，含一个具体数字；② 第 1 条必须是结论性判断，不是数据复述；
③ 读完后总经理能直接决定要不要追问毛利率。
边界：不写套话（"持续发力""稳中向好"）；不推测素材里没有的数字；
如果数据自相矛盾，在要点末尾用「⚠️ 待核」标出并说明矛盾在哪。
输出：只输出 5 条，编号 1–5，不要前言、不要总结段。
```

差异点：没有"先分析再归纳"的步骤说明；用 effort 档位（中/高）控制深度；长度靠一条具体字数规则压住。

**B. Claude 5.x**——XML 分区、示例带一个"不合格样例"：

```
<role>你是华东区销售负责人，向总经理做季度书面汇报。</role>

<documents>
<doc id="q3">粘贴 Q3 数据全文</doc>
</documents>

<task>从 <doc id="q3"> 中提炼 5 条要点，按重要性排序。</task>

<rules>
- 每条 ≤40 字，必须含一个来自 <doc id="q3"> 的数字
- 第 1 条是结论性判断（如"增长靠新客、老客在流失"），不是数据复述
- 禁止套话：持续发力、稳中向好、再创佳绩
- 素材没写的数字不许补；矛盾处标「⚠️ 待核」
</rules>

<example>
<good>1. 营收 1.82 亿、同比 +9%，但毛利率降 1.8pt 至 31.4%，增长质量在下降。</good>
<bad>1. 本季度华东区持续发力，取得了稳中向好的成绩。（无数字、无判断，不合格）</bad>
</example>
```

差异点：用 `<documents>` 包长素材、`<example>` 里给一正一反；不写 prefill（会被 400）；长度只靠 prompt 里的字数规则。

**C. Gemini 4 / 3.1**——多给示例、少给抽象指令：

```
任务：把下面的销售数据改写成给总经理的 5 条汇报要点。

数据：
粘贴 Q3 数据全文

示例 1（好）：
输入：营收 5000 万（同比 -3%），新客 12 家，老客流失 4 家
输出：1. 营收 5000 万同比 -3%，新客增量未能补上老客流失，净流失 4 家。

示例 2（好）：
输入：库存周转 58 天（+6 天）
输出：2. 库存周转拉长 6 天至 58 天，占用现金增加，属可立改项。

示例 3（不合格）：
输出：3. 团队将持续发力，力争再创佳绩。
（不合格原因：没有数字、没有判断、不可执行）

要求：仿照示例 1、2 的结构写 5 条，每条 ≤40 字，第 1 条必须是结论。
```

差异点：三个示例替代了一大段规则说明（官方明确"示例够清楚可以少写指令"）；不写 temperature（会被忽略）；分隔符（示例 1/2/3 的写法）必须与输出格式一致。

## 5. 迁移清单（从 A 换到 B 时，照着删/照着加）

| 迁移方向 | 删掉 | 加上 | 换完先验什么 |
|---|---|---|---|
| 任意 → Claude 4.6+ | 所有 prefill、以 assistant 开头的续写 hack、期待"格式被强制"的写法 | XML 分区；`<example>` 里的一正一反 | 发一次带 prefill 的请求，确认是 400 而不是被静默忽略 |
| 任意 → Gemini 4 | 全部 temperature / top_p 调参建议、"调低温度更稳定"这类备注 | 2–3 个 few-shot 示例；一致的示例分隔符 | 同一提示词跑两遍，看格式是否稳定（不再靠温度保稳定） |
| 任意 → OpenAI 推理模型 | "一步步想""先列思考过程""第一步…第二步…"、temperature/top_p、"请深入思考" | 目标 + 成功标准 + 边界 + 交付格式；effort 档位建议 | 关掉 effort 调高后，看输出是否变长但没变好——若是，改成功标准而非加步骤 |
| 推理模型 → 通用聊天模型 | "直接给结论"这类省略过程的要求（通用模型需要你给方法） | 1–3 个示例、输出契约、明确动词 | 用同一输入跑，看格式是否漂移；漂了就补示例而不是加形容词 |
| 通用 → 小模型/本地 | 多任务混写、长背景故事、开放式创作要求 | 示例加到 3–5 个、格式要求写成"只输出 X"、任务拆成单步 | 连跑 3 次看格式是否还守规矩；不守就再砍指令 |
| 文本 → 图像/视频 | 所有否定句、引号包裹的文案、抽象形容词（"高级感""氛围感"） | 正向负面描述（"墙面干净"）、镜头与光线词、比例、一个场景一段 | 出图后看画面里有没有渲染出文字——有就是引号没删干净 |

迁移备注要写进交付物的"模型适配备注"一节，格式：**换到 X：删 A、加 B、验 C**，三句话以内。

填好的迁移备注（交付物里就这么写，不要写"建议按模型调整"）：

> **目标模型**：Claude 5.x，开 extended thinking。**已删**：prefill 续写、"一步步思考"、`temperature 0.2`。
> **已加**：`<documents>` 包长素材、`<example>` 一正一反、末尾复述 3 条约束。
> **上线前验证**：① 故意发一次带 prefill 的请求，确认是你预期的报错行为；② 同一输入跑 3 次，看格式与条数是否漂。

## 6. 常见坑

- 不要在提示词里写死型号版本号（"你是 GPT-6"），改写模型类型（"如果你内置思考，直接给结论"）。
- 不要给推理模型写"请一步步思考"，改写成功标准和边界——步骤是它的活，判断才是你的活。
- 不要为了"格式稳定"去调 temperature 或塞 prefill，改用 structured outputs / JSON schema。
- 不要把示例堆到 10 个以上求保险，改留 2–3 个**典型且互不相同**的示例，再补一条反例。
- 不要把"换模型"当成换个名字，换模型必须重测一次格式与长度（这是最容易被漏掉的一步）。
- 不要在一份提示词里兼容所有模型（写一堆"如果用 A 就…如果用 B 就…"），按目标模型出一版，迁移建议另附。
