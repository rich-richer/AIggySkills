# 学习模式（Learning）

> 什么时候读这个文件：要搞懂一个概念、让人给你讲清楚、把一本书／一门课变成能复述的知识，或者想被追问到真正会。
> 读完你会得到：一个"按我的水平分层讲 + 费曼检验 + 一次一问 + 自测"的学习提示词骨架，一张必问清单，一个填好的完整示例，以及不会变成百科复述的写法。

## 什么时候用

- 用户会这样说："用大白话讲讲什么是 XX""我看了三遍还是不懂""考我一下""帮我解释这个概念"。
- 用户不是要一份资料，而是要**能在脑子里重建**的理解（能复述、能判断、能用在具体问题上）。
- 用户水平参差：可能是零基础，也可能是"知道名词但不会用"。
- 需要纠正误解，而不只是灌入新信息。
- 学完要产出点什么：一次分享、一个决策、一次考试。

## 骨架

```
# 学习任务：{{概念／主题}}

## 我的起点
- 我已经会：{{……}}
- 我不会：{{……}}
- 我要用它来：{{具体场景 + 时间／听众}}
- 我能投入的时间：{{X 小时／分几次}}

## 讲解顺序（严格按此顺序，不要合并）
1. 一句话定义：≤{{30}} 字，不带术语
2. 它解决什么问题：先讲"没有它会怎样"，用一个我熟悉的场景
3. 一个比喻：必须写清"这个比喻在哪里会失效"
4. 正式定义：这时候才允许出现术语，术语首次出现给英文
5. 一个算得出来／走得通的例子：用我给的数字，每一步都写出来，不要跳
6. 我可能误解的 3 个点：每条写成"错误理解 → 正确理解"

## 事实纪律
- 涉及公式或推导，每一步都要能被我自己验证；不确定的地方标"（待核实）"，不要编一个顺眼的数
- 只讲这个主题在我场景里够用的部分，不要扩展到整个学科
- 不要用"研究表明"这种无主语说法

## 费曼检验
讲完后，让我用一句话向你解释它；你只做三件事：
指出我这句话里错的部分、漏的部分、以及"我说对了但其实没懂"的部分。

## 追问方式（一次只问 1 个）
从这三个方向里挑，一次只问一个问题，等我回答再问下一个，不要一次列 10 个问题：
- 边界：什么情况下这个结论不成立？
- 反例：有没有看起来符合、但实际不符合的例子？
- 对比：它和 {{相邻概念}} 的差别到底在哪？

## 自测
最后给我 3 道选择题 + 1 道开放题，用我上面说的真实场景出题。
答案单独放在最后，不要提前泄露。
```

## 必问信息

| 编号 | 问题 | 为什么必须问 | 缺省假设 |
|---|---|---|---|
| I-L1 | 你现在会什么、不会什么？拿一件你会的事当参照 | 不写起点，模型默认按大学教材讲；写"我会 Excel 透视表"比写"我基础一般"有用一百倍 | 默认"会日常办公软件，没有该领域的系统训练" |
| I-L2 | 学完要干什么？讲给别人听、做决策、还是考试？偏好哪种形式（长文／对话／图解）？ | 用途决定深度和检验方式；要讲给别人听就必须过费曼检验 | 默认"3 天内要能讲给同事听"，形式用对话式分步 |
| I-G1 | 你会在什么场景下用它？能给一个真实例子吗？ | 抽象讲解必然平庸，挂一个真实场景才有锚 | 默认用用户给的业务场景 |
| I-G3 | 有哪些"不想学"的部分（推导过程／历史／学派争论）？ | 不划边界，模型会把整个学科都讲一遍 | 默认只讲够用部分，不展开历史 |
| I-G4 | 这是一次性问答，还是要做成长期学习的文档／人设？ | 一次性就对话推进；长期学要沉淀成笔记，（本 skill 不提供长期人设模板） | 默认一次性对话 |
| I-F1 | 我复述一下你的起点、目标、时间预算，对不对？ | 起点错一格，整段讲解都白讲 | 默认按已给信息开始，并在第一段自报我理解的起点让你校正 |

## 组装规则

1. **起点写得越具体越好，最好带一个"会"的参照物。** "我会用 Excel 做透视表，不会概率论"能让模型自动选对类比；"我基础一般"只能得到中等难度的百科。
2. **顺序与教材相反：先问题与比喻，再正式定义。** 成人自学更需要先建立直觉；正式定义放第 4 步，是为了让后面的术语有挂靠点（经验规则，非实测）。
3. **苏格拉底追问必须写死"一次只问 1 个"。** 不写死，模型会给你 10 个问题清单，你就变成在做题而不是在对话。
4. **比喻必须标"失效边界"。** 不标边界的比喻会被当成定义用，是学错概念最常见的路径。
5. **可删与必留。** 正式定义在"只求会用"时可以删掉；费曼检验和自测**不要删**——它们是判断"真会了没有"的唯一手段。
6. **交付六件套**（按 SKILL.md 的六件套交付）：讲解提示词、变量说明、一句用法（新开对话、先给起点）、2 条追问话术、1–3 条 eval（含"只有百科复述即不合格"的反例）、模型适配备注。

## 填好的示例

```
# 学习任务：贝叶斯定理（下周三要给团队讲 15 分钟）

## 我的起点
- 我已经会：Excel 透视表、算平均数、看懂百分比
- 我不会：概率论术语、条件概率公式、任何矩阵
- 我要用它来：判断我们 A/B 测试的结果是不是噪声，讲给 8 个运营同事听，他们和我水平差不多
- 我能投入的时间：总共 3 小时，分 3 次

## 讲解顺序（严格按此顺序，不要合并）
1. 一句话定义：≤30 字，不带术语
2. 它解决什么问题：先讲"没有它会怎样"，用我们的 A/B 测试场景
3. 一个比喻：必须写清这个比喻在哪里会失效
4. 正式定义：这时候才出现术语，术语首次出现给英文
5. 一个算得出来的例子：用我这次的数据——对照组 2400 人，转化 192 人（8%）；
   实验组 2400 人，转化 264 人（11%）。每一步都写出来，不要跳步
6. 我可能误解的 3 个点：每条写成"错误理解 → 正确理解"

## 事实纪律
- 每一步都要能被我自己手算验证；不确定的地方标"（待核实）"，不要编一个顺眼的数
- 只讲这个定理在这个场景够用的部分，不要扩展到整个统计学派
- 不要用"研究表明"这种无主语说法

## 费曼检验
讲完后让我用一句话向你解释它；你只做三件事：
指出我这句话里错的部分、漏的部分、以及"我说对了但其实没懂"的部分。

## 追问方式（一次只问 1 个）
从这三个方向里挑，一次只问一个问题，等我回答再问下一个：
- 边界：什么情况下"看绝对转化率涨了就上线"这个判断会错？
- 反例：有没有看起来差异很大、其实完全可能是噪声的例子？
- 对比：它和"多跑一周再看看"的差别到底在哪？

## 自测
最后给我 3 道选择题 + 1 道开放题，用我们真实的 A/B 测试数据出题。
答案单独放在最后，不要提前泄露。
```

**这段为什么这样写：** "对照组 2400 人转化 192 人"这种带数字的算例，比任何"举个例子"都更能逼出可验证的推导；"指出我说对了但其实没懂的部分"是费曼检验里最有价值的一问——它直接把"背下来的解释"和"理解"分开；三个追问方向分别打边界、反例、对比，覆盖了概念掌握的三道关。

**两条追问话术：**
- "第 5 步你跳过了先验概率怎么来的。用我这次的 8% 从头算一遍，每一步都写数字，不要用术语概括。"
- "把第 3 步那个比喻的失效边界再说清楚一点：在什么情况下用这个比喻会得出错误结论？给一个具体例子。"

**两条 eval case：**
- ✅ 合格：第 5 步的每一步都能被手算复现（8%、11%、样本量都在算式中出现），且第 6 步至少一条误解是用户真实会犯的（如"11% 比 8% 高，所以一定有效"）。
- ❌ 不合格：通篇是"贝叶斯定理是概率论中的重要定理……"的百科式复述，没有用用户的 A/B 数据、没有费曼检验——判不合格，退回重写第 2、5 步。

## 模型适配

- **推理模型：** 不要写"请一步步思考"——三家厂商一致反对给推理模型堆 CoT（见 `../anti-patterns.md` 的已证伪清单）。但**要求它输出可核对的推导步骤**是输出格式要求，不是让它暴露内部思维链，可以保留。
- **通用聊天模型：** 明确讲解顺序 + 一个"合格讲解段落"的样例。Claude 用 `<my_level>` `<goal>` 分区；Gemini 给一条 few-shot（"讲解片段 + 自测题各一"）。
- **小模型／本地模型：** 一次只讲一个子概念，比喻只用 1 个，自测题砍到 2 道；不要让它同时讲定义、推导和应用。
- **图像／视频模型：** 本模式不直接出图；需要示意图时，把"要表达的结构"按 `./image-video.md` 转成画面描述，再回到对话里讲解。

## 常见坑

1. 不要问"请详细解释 XX"——得到的必然是百科复述；换成"用我这次 A/B 测试的数据讲"。
2. 不要一次让它列 10 个追问——写死"一次只问 1 个"，否则你会在做题而不是在被追问。
3. 不要用"你是诺贝尔奖级别的物理学家"来提准确度——角色设定对事实召回没有增益（见 `../anti-patterns.md`；162 角色 × 2410 题无提升）。
4. 不要让比喻代替定义——比喻必须附失效边界，否则学到的是一句顺口溜。
5. 不要只"讲"不"检验"——费曼复述和自测是判断学会没有的唯一手段，省了就白学。
6. 不要让它一口气讲完一个学科——按"一次一个概念 + 一次一个问题"推进，学完再开下一个（李厂长 秘籍 8：指令过多要拆）。
