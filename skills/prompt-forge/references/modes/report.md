# 报告模式（Report）

> 什么时候读这个文件：要交一份会被人做决策用的方案、可行性分析、汇报材料或 BP，而不是写一篇介绍性文章。
> 读完你会得到：一个"决策者—结论—方案对比—风险—下一步"的报告骨架，一张必问清单，一个能直接改数字复用的填好示例，以及长报告的三轮分步写法。

## 什么时候用

- 用户会这样说："帮我写个方案""做个可行性分析""下周要跟老板汇报""这个 BP 帮我顺一下"。
- 交付物有**明确的读者和明确的时间点**（周会、投委会、董事会），过期就废。
- 读者要做的不是"了解"，而是"批准／否决／选一个"。
- 内容里必须给出成本、收益、风险和下一步，而不只是背景与愿景。
- 篇幅通常在 2000 字以上或 10 页以上，一次生成容易结构塌陷。

## 骨架

```
# 报告任务：{{报告名}}

## 谁的决策，什么时候做
- 决策者：{{角色}}
- 他要在 {{日期}} 的会上决定：{{A／B／C 中的一个具体选项}}
- 如果他只读第一页，必须记住的一句话：{{……}}
- 他最可能反对的一点：{{……}}（报告里必须正面回应）

## 结论（先写，不要留到最后）
- 推荐：{{选项 X}}
- 三条核心理由：{{理由 1}}／{{理由 2}}／{{理由 3}}
- 置信度：{{高／中／低}}，因为最大的未知是 {{……}}
- 与直觉相反的一点：{{如果找不到，就写"没有"}}

## 方案对比
| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 一次性投入 | | | |
| 12 个月总成本 | | | |

| 最大风险 | | | |
| 退出成本 | | | |

## 数字与假设
- 已知数据（带来源）：{{……}}
- 我们的假设：{{每条假设后面写"如果这条错了，结论会变成什么"}}
- 口径说明：{{收入／成本分别是含税还是不含税、是否含人力}}

- 最大的 3 个风险 + 触发信号 + 止血动作（什么条件下停止投入）

## 格式
- {{全文 2500 字左右／正文 10 页}}，Markdown，一级标题不超过 5 个
- 每页最多 1 张表；数字保留到万位，不要写 3~4 位小数
```

## 必问信息

| 编号 | 问题 | 为什么必须问 | 缺省假设 |
|---|---|---|---|
| I-P1 | 决策者是谁？他要在哪天、决定什么？ | 报告的每一段都应该服务于"让他做这个决定"；没有决策时点，报告会写成介绍文 | 默认给业务负责人，两周内做"做／不做" |
| I-P2 | 你倾向哪个方案？报告要中立比较，还是要论证某一个？ | "中立分析"和"推荐方案"是两种文体；不说清就两头不讨好 | 默认中立比较 + 明确推荐，理由单独写 |
| I-P3 | 要不要写成本、风险、退出条件？ | 决策者最关心的就是这三样；不写就等于没做可行性 | 默认全写，且风险段必须有"止血动作" |
| I-G2 | 有没有你认可的历史报告可以当格式样板？ | 组织内部有固定模板时，结构比内容更容易被打回 | 默认按骨架五段结构 |
| I-G3 | 有哪些数字或结论不能出现在这份文件里？ | 商业报告经常涉及未公开数据、竞对信息、员工人数 | 默认只写用户提供的数字，未提供的一律标"待核实" |
| I-G5 | 已有的材料（财务表、报价、竞品资料）有哪些？ | 报告的可信度来自带来源的数字，不是文笔 | 默认用户会补数据；缺数据就先产出"数据缺口清单" |
| I-E3 | 期望篇幅？ | 800 字备忘和 20 页 BP 是两种任务 | 默认 2500 字 Markdown 正文 |
| I-F2 | 要不要先给一版只有目录 + 5 条结论的骨架？ | 报告返工成本高，先对骨架能省一大半时间 | 默认先出骨架 |

## 组装规则

1. **顺序：决策者与决策时点 → 结论 → 方案对比 → 假设 → 风险 → 下一步。** 结论段放在骨架前半部分，模型会更认真地对待它；放到文末它就会被写成"综上所述"。
2. **长报告用三轮分步引导**（Axton《重构个体》5.3.3 分步引导）：① 先只要 3–5 个核心洞察点；② 根据洞察点拟三级大纲；③ 按大纲分节填，每节 300–500 字。一次要 8000 字，结构必塌。
3. **每个数字二选一：带来源，或标"假设"。** 这是报告可信度的分界线；混在一起写，读者会默认全是编的。
4. **反方评审可选但强烈推荐：** 定稿后加一轮"五顾问"审查（反驳者／本质派／扩张者／代价计算者／执行者），每条顾问只保留最狠的一句，再决定改不改（prompt_library 五顾问评审法）。
5. **可删与必留。** 行业背景可以压成附录；决策时点、方案对比表、风险止血、下一步这四块必留。
6. **目标段写成动词句，可选三步升级。** 「谁的决策，什么时候做」一段用名词换动词的写法（`在…内，让谁…决定什么`）；需要更高的高度时，按 `../techniques/ambition-4d.md` 第 3 节逐级加：先要故事 → 再要最紧迫的 3 个决策 → 最后（形式非指定时）请它提出比现有报告形式更好的机制。
7. **交付六件套**（按 SKILL.md 的六件套交付）：正文、变量说明、一句用法、2 条追问话术、1–3 条 eval（含"只讲优点不讲退出成本"的反例）、模型适配备注。

## 填好的示例

```
# 报告任务：连锁健身房是否上线"晚间无人值守 + 自助饮品柜"

## 谁的决策，什么时候做
- 决策者：总经理与财务负责人
- 他要在 12 月 18 日经营会上决定：A 只做无人值守（不投饮品柜）／B 两者一起上／C 都不做
- 如果他只读第一页，必须记住的一句话：B 方案 26 万元投入，按我们的夜间到店率，回本要 19 个月，比我们对新店的要求慢 7 个月
- 他最可能反对的一点：无人值守期间的会员纠纷和器械损坏谁负责（报告里必须正面回应）

## 结论（先写，不要留到最后）
- 推荐：先做 A（无人值守），饮品柜延后 6 个月
- 三条核心理由：夜间 21:00–23:00 到店人次占全天的 9%；4 家店里有 3 家夜间人力成本每月 1.8 万元；
  饮品柜的毛利改善依赖客单价，而我们夜间客单价只有日间的 62%
- 置信度：中，因为夜间到店数据只有最近 3 个月（9 月新装的闸机才开始统计）
- 与直觉相反的一点：夜间人不多的店，反而更适合先上无人值守——人力省下来的钱是确定的，饮品柜收入是不确定的

## 方案对比
| 维度 | A 无人值守 | B 两者一起上 | C 都不做 |
|---|---|---|---|
| 一次性投入 | 9 万元（门禁+监控+保险柜） | 26 万元 | 0 |
| 12 个月总成本 | 9 万 + 保险 1.2 万 | 26 万 + 保险 1.2 万 | 夜间人力 21.6 万 |
| 回收期 | 11 个月 | 19 个月 | — |
| 最大风险 | 纠纷责任界定不清 | 现金流压力 + 两件事同时试错 | 夜间时段持续亏人力 |
| 退出成本 | 设备可迁移到新店 | 饮品柜折旧 3 年 | 0 |

## 数字与假设
- 已知数据：4 家店，会员 6800 人；2025 年 9–11 月夜间（21:00–23:00）到店 4210 人次，占全天 9%
  （来源：闸机系统导出，2025-11-30）
- 假设：无人值守后夜间到店增加 15%（依据：同类门店经验，非实测）
  → 如果只增加 0%，回收期从 11 个月变成 17 个月，结论不变；如果增加 30%，A 的回收期缩到 8 个月
- 口径：金额均为含税；人力成本含社保，未含店长分摊

## 风险与止血
- 风险 1：夜间纠纷无第三方见证 → 触发信号：单月夜间投诉 ≥2 起 → 止血：暂停该店夜间时段，恢复值班
- 风险 2：器械损坏率上升 → 触发信号：月度维修成本超 3000 元 → 止血：先加监控点位，不加设备
- 合规：门禁改造需物业书面同意；夜间经营时段需核对租赁合同条款（待核实）

## 下一步（30 天内可执行）
| 时间 | 动作 | 负责人 | 产出 |
|---|---|---|---|
| 12/19–12/25 | 与物业确认门禁改造与夜间条款 | 运营总监 | 书面回函 |
| 12/26–1/10 | 选 1 家店试点，装门禁与监控 | 工程 | 验收单 |
| 1/11–1/31 | 试点店数据复盘 | 运营 | 一页复盘 |

## 格式
- 全文 2500 字左右，Markdown，一级标题不超过 5 个
- 每页最多 1 张表；金额保留到万位
- 禁用词：赋能、抓手、闭环、生态位、护城河
```

**这段为什么这样写：** "他最可能反对的一点"逼着报告正面回应质疑，而不是绕开；方案对比表把"退出成本"列进去，是因为决策者真正怕的不是花钱，是花错了收不回来；假设区写了"如果只增加 0% 结论会怎样变"，把不确定性从"感觉"变成"可计算"。

**两条追问话术：**
- "把方案 A 回收期的计算过程一步一步写出来：每一笔成本和每一笔节省分别是多少、按几个月摊。"
- "你写的'夜间到店增加 15%'依据是什么？如果是同类门店经验，把来源换成我们能查到的数据，或者改成三个情景（0%／15%／30%）分别给结论。"

**两条 eval case：**
- ✅ 合格：第一页出现"26 万／19 个月／比要求慢 7 个月"三个可验证数字，且风险段有触发信号。
- ❌ 不合格：整篇只有优点、没有退出成本、风险写"需关注市场变化"——判不合格，退回重写风险与假设两段。

## 模型适配

- **推理模型：** 只给决策者、选项、已知数据、输出结构；不要写"先列出利弊再权衡"的步骤。深度靠 effort 档位，不靠提示词里写"请深入思考"（见 `../models.md` 的模型分叉表与判断规则）。
- **通用聊天模型：** 结论先行 + 一张对比表 + 明确字数。Claude 用 XML 分区（`<decision>` `<options>` `<constraints>`）；Gemini 给一段"结论先行"的样例输出当 few-shot。
- **小模型／本地模型：** 只做"结论 + 一张对比表 + 三条风险"，删掉背景与附录；表格列数砍到 3 列。
- **迁移提醒：** 换 Gemini 4 要补示例、删 temperature 调节；换 OpenAI 推理模型要删"一步步分析"这类措辞（见 `../models.md` 的模型分叉表）。

## 常见坑

1. 不要写"请帮我写一份全面的可行性报告"——改成"谁在什么时候决定 A／B／C 中的哪一个"；没有决策句就没有报告。
2. 不要先写背景再写结论——结论放前面，模型才会围绕它取舍材料。
3. 不要把假设和事实混在一段——每个数字后面二选一：标来源或标"假设"。
4. 不要一次要 8000 字——用洞察点→大纲→分节填的三轮法，结构才不塌（Axton 5.3.3）。
5. 不要漏掉"退出成本"和"止血动作"——决策者最怕的不是投入，是收不回来。
6. 不要用"赋能／抓手／闭环"——这些词在报告里等于没写；一律换成具体动作（"把审批从 5 天压到 2 天"）。
