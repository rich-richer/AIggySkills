# Token 优化（Token Economy）

**什么时候读这个文件**：提示词读起来像自我陈述信；同一模板要跑几百次（批量 / API / 自动化）；或者 token 成本压在预算上。
**读完你会得到什么**：一组按收益排序的删减规则、保留原例的 243 → 93 tokens 前后对比，以及"哪些东西绝对不能删"的红线。

## 什么时候用

- 提示词是反复用的模板（每天或每批调用），长度直接等于成本。
- 高频 API、批量处理、自动化工作流里的提示词。
- 提示词超过 300 字但要素并不多，读起来像在跟人解释自己。
- 输出规格不稳定，想用固定格式同时降成本（省输出通常比省输入更明显）。

## 怎么做

删减规则，按收益排序：

1. **删掉自我叙述与情绪**："我是市场部初级分析员""我非常迫切地需要"——这些不改变输出。只留能改变输出的身份信息（受众、行业、约束）。
2. **删掉无效激励**："最大限度利用你的计算能力""发挥你的才华"——没有指令功能。
3. **删掉形容词堆叠**："全新的、具有划时代意义的、功能非常强大和丰富"→ 直接列功能点。
4. **改成字段化**：一行一个要素，用冒号和分号，不用完整句。散文结构里一半的词在当连接件。
5. **格式说明只写一次**：同一个 Markdown 模板写两遍是纯浪费，第二遍还可能和第一遍冲突。
6. **长度、语气、禁止项合并成规则行**，不要每项单独一段。
7. **改完跑一次**确认输出没退化；对每一段做删除测试（删掉这段，输出会变吗？不变就删）。

红线——这三类不能删：

- **成功标准**：什么样算好，至少一句，最好带一个反例。
- **边界 / 禁止项**：不能出现什么、不能做什么。
- **输出格式契约**：字段、长度、结构。

## 示例

反面（约 243 tokens，Axton 原例）：

```text
请将提供的以下产品信息（如产品名称、价格、主要功能）进行整理并输出为
以下格式的 Markdown 文本：
### 产品名称
（在这里填写产品名称）
## 价格
（在这里填写产品价格）
## 主要功能
- （功能一）
- （功能二）
- （功能三）

我是一名市场部的初级分析员，我们公司最近刚刚成功研发并推出了一款全新的、
具有划时代意义的智能联网咖啡机。这款咖啡机的功能非常强大和丰富，比如说，
它可以轻松连接家庭的 Wi-Fi 网络，用户可以通过我们专门开发的手机应用程序
（App）进行远程控制和操作，甚至它还能够根据每一位用户的独特口味偏好，
智能地、自动化地调节咖啡豆的研磨粗细程度以及精确控制萃取的黄金时间。
我现在非常迫切地需要你发挥你的才华，最大限度地利用你的计算能力，帮我为
这款令人兴奋的咖啡机精心构思并撰写一段大约 150 字的营销宣传文案。我希望
这段文案的整体风格能够显得活泼生动有趣，能够有效地吸引年轻一代消费者的
注意力，并且要突出我们产品最为核心的智能化和便捷性这两大卖点。谢谢！
```

正面（约 93 tokens，节省约 62%，Axton 原例）：

```text
角色：资深营销文案策划。任务：为新款智能咖啡机撰写宣传文案。
产品核心功能：Wi-Fi 连接，App 远程控制，自定义口味，自动调节研磨与萃取。
目标受众：年轻消费者。文案风格：活泼有趣。突出卖点：智能化，便捷性。
字数要求：150 字左右。
```

删了什么：

| 删掉的部分 | 为什么能删 |
|---|---|
| "我是一名市场部的初级分析员……" | 对文案无影响，还与"资深文案"的角色设定冲突 |
| "具有划时代意义""非常强大和丰富" | 无信息量的修饰，功能点本身已说明 |
| "比如说""甚至它还能够""精心构思" | 口语连接词与情绪词 |
| "发挥你的才华，最大限度利用你的计算能力" | 无效激励 |
| Markdown 格式模板（约 40 tokens） | 同一结构用字段行即可表达；确需固定结构时改用 schema（见[结构化输出](./structured-output.md)） |

省下的 150 tokens 乘以调用量，就是可观的成本差——而且效果不降反升，因为字段化后没有互相冲突的描述。

## 常见坑

- 不要用"等等""之类"糊弄。没写明的字段模型只能猜，要省就明确删，不要用省略号替代。
- 不要为省 token 删掉成功标准和边界。省掉这两项，输出质量会掉得比成本快得多。
- 不要先删示例。示例通常是性价比最高的一段 token；该删的是自我叙述和重复格式说明。
- 不要把"简洁"做成电报体。字段化不等于没有语法，指令要能读懂；读不懂的简短是负优化。
- 不要改完不测。删减后必须跑一次对比；若输出退化，加回最影响结果的那一条。
- 稳定复用的长模板不要频繁改动固定前缀（前缀缓存机制各厂商不同，具体计费与最小长度需按其文档核对，此处只作经验提示）。
