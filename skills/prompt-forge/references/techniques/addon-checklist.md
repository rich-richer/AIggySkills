# 通用附加指令清单（Add-on Checklist）

**什么时候读这个文件**：你想给每条提示词尾部加一段"例行内容"；或者反过来，你正在把所有提示词写成小作文。
**读完你会得到什么**：7 条可粘贴的附加条款、每条的启用与禁用场景、以及一份精简版附加包（全塞进去通常适得其反）。

## 什么时候用

- 要写一条会在不同任务之间反复复用的通用提示词。
- 输出经常犯同类毛病（不核实时效、术语不解释、上来就长篇大论）。
- 用户说"加个兜底要求""让 AI 先问我再答"。
- 你要给团队一份"提示词结尾固定带这段"的规范。
- 体检别人的提示词时，用它当缺项检查表。

## 怎么做

清单是**可选条款**，不是必装插件。逐条判断，只留用得上的。

| # | 条款 | 一句话要求 | 什么时候启用 | 什么时候别用 |
|---|---|---|---|---|
| 0 | 澄清模糊点 | 信息不全时先提问，明确后再输出；信息够就直接做，不为提问而提问 | 需求模糊、跨部门、影响面大 | 单次小任务；用户明确说"别问了直接给我" |
| 1 | 时效与信源 | 说明知识截止；随时间变化的事实（价格 / 版本 / 职位 / 政策）须核实；中英信源都覆盖；过时信息标注"原信息 → 最新情况（截止日期）" | 数据、价格、政策、人事、模型版本类问题 | 纯逻辑推演、创意写作、内部私有信息 |
| 2 | 顾问级分析视角 | 用资深顾问的分析框架，先调研后方案 | 战略 / 方案 / 行业分析类交付 | 事实查询、代码、格式转换——头衔不提升准确度 |
| 3 | 术语与双语 | 术语首次出现加英文；结尾统一汇总术语对照表 | 技术 / 专业内容、跨语言、要给别人看 | 日常沟通、口语化文案（会毁掉语感） |
| 4 | 任务类型判定 | 先判断属于元提示 / 总结 / 分类 / 学习 / 操作 SOP / 其他，再决定深度与格式 | 一份提示词要处理多种输入类型时 | 任务类型已经写死的单一任务 |
| 5 | 多模态专项 | 视频要同时分析音频与画面，不能只看字幕或转录 | 输入是视频、录屏、带图文档 | 纯文本任务 |
| 6 | 准确性核查 | 输出前核实关键结论；无法核实的标"未核实，请自行确认" | 会进入决策链的交付物 | 头脑风暴、探索性草稿 |

**清单精神（元规则）**：保持简洁可执行。堆成大段说明文字没人照做，还会稀释真正的重点。所以上表是"选装"逻辑，不是"全装"逻辑。

选装怎么落地：一条提示词留 1–3 条附加条款就够。推荐默认组合——`0 澄清` + `1 时效`（涉及外部事实时）+ `6 准确性核查`（交付物要给别人看时）。

## 示例

差（7 条全塞，写成 400 字小作文，模型重点被稀释）：

```text
[正文任务]……
此外：请先澄清模糊点；请说明知识截止并联网核实最新情况；请以麦肯锡、高盛
级别资深顾问水准作答；请所有术语中英对照并在结尾附术语表；请先判断任务
类型再决定输出方式；视频需结合音频与画面；输出前请核查准确性；请保持
清单简洁可执行……
```

好（精简到 3 条，每条都能执行）：

```text
[正文任务]……

【附加要求】
1. 若上面有信息不足或歧义（尤其"{{受众}}"和"{{篇幅}}"），先向我提问，
   我回答后再输出。
2. 涉及价格、版本、政策等会变的事实，请先说明你的知识截止日期；
   无法联网请标注"（知识截止 {{日期}}，可能已过时）"。
3. 输出前检查每个数字和结论；无法核实的，在句末标"（未核实，请自行确认）"。
```

说明：三条各管一类失败——信息不足、事实过时、事实无依据。术语表、任务分类、多模态这些跟本次任务无关，塞进去只会占注意力。

## 常见坑

- 不要 7 条一次性全贴到每条提示词。附加条款是有成本的：占 token、稀释重点，还会跟正文约束打架。
- 不要用"顾问级视角"背书事实。"麦肯锡、高盛级别"改的是语气和结构期待，不会让数据变准；事实要靠材料和[引用锚定](./citation-anchoring.md)。
- 不要要求联网却不说清模型不能联网时的行为。补一句"无法联网就标注知识截止日期"，否则它会假装查过。
- 不要跟"直接给我结果"的用户需求对着干。澄清条款在单次任务里可以关；先问三句才给答案，体验会很差。
- 不要把双语术语写进正文每一句。要求首次出现加英文 + 结尾统一列表，正文才读得下去。
- 不要让附加条款越写越长。清单的原始精神就是"简洁可执行"；超过 5 条就该问"哪条真的改变过输出"。
