# 任务拆解：三段论 / 分步引导 / 提示词链（Decomposition）

**什么时候读这个文件**：一条提示词塞了太多任务、模型开始"不听话"；或者输出很长、中间需要人审。
**读完你会得到什么**：三段论与三轮分步引导两种拆法、把链条接起来的引用写法，以及一条明确的反向判断——什么时候不该拆。

## 什么时候用

- 一条提示词里有 3 个以上不同性质的活（提取 + 创意 + 成文 + 配图）。
- 输出很长（超过 1500 字），你没法一次审完。
- 中间产物有价值（洞察点、大纲、方案列表），你想在中间拦一下。
- 模型漏做其中一步，或把多步揉成一步糊过去。
- 要固化成自动化工作流（每步一个模块，串起来）。

## 怎么做

1. **先做"拆不拆"的判断**（见下节"什么时候不该拆"）。判据：能列出 ≥3 个不同性质的阶段产物，或约束互相打架，才拆。
2. **用三段论切**：感知（把原始素材变成结构化信息）→ 策略（基于信息出方案 / 创意）→ 输出（把方案写成成品）。分段的分界不是字数，而是"这一段的产物是什么"。
3. **每段显式引用上一段产物**：用占位写法把上游结果贴回来，例：`基于上一轮的分析（设计特点：【引用 Output A 的设计特点】；受众：【引用 Output A 的受众判断】）`。不引用就会出现凭空续写。
4. **或用三轮分步引导**：第 1 轮只出洞察点（3–5 条）→ 第 2 轮只出三级大纲 → 第 3 轮按大纲分段成文（每段单独发）。适合长报告。
5. **中间产物外置**：把 Output A 存进文件或笔记，下一轮用文件内容而不是"你刚才说的"。多轮对话的记忆不可靠，隔久了或换会话就没了。
6. **收束**：流程稳定后可以合并成一条提示词（省一轮成本），或者直接固化为自动化模块。

三条链怎么选：

| 场景 | 用哪种 | 理由 |
|---|---|---|
| 有原始素材要变成成品（海报 → 分析 → 推文） | 三段论 | 每段产物明确，容易验收 |
| 长文档、长报告 | 三轮分步引导 | 大纲可人审，返工成本低 |
| 固定的重复任务 | 提示词链 | 每步可独立优化、可并行、可接工具 |

### 什么时候不该拆

- **单轮能完成的小任务**。拆成三步只是多付两轮成本，还多了两次信息损耗。
- **需要整体审美的创造性任务**。先拆会让风格在各段之间割裂；这类任务先整体出稿再局部改（见[乒乓球迭代](./pingpong-iteration.md)）。
- **推理模型的内部分析**。给内置思考的模型指定"先做 A 再做 B"属于官方反对的"指定思考步骤"，它自己的规划通常更好。拆解只用于"产物确实要分开交付"的场景。
- **还没试过一次就拆**。先零样本跑一遍，看它到底在哪一步垮；很多任务一次就过。
- **拆到每句一个提示**。粒度以"产物"为单位，不是以"动作"为单位；产物相同或相近的两步应该合并。

## 示例

差（一条提示词四合一）：

```text
分析这张咖啡机海报，提取卖点，然后写三个推文创意，选一个扩写成
100–120 字的图文帖，并配一张 1:1 的图。
```

→ 四件事一件比一件轻，模型会把注意力花在前半段，后半段敷衍了事。

好（三段论，海报案例的收束版）：

```text
【第 1 段｜感知与信息提取】
你是市场洞察助理。观察这张咖啡机海报，输出三项：
1. 不超过 50 字，描述外观设计最显著的 3 个特点；
2. 提取海报上所有与功能 / 参数相关的文字，列表呈现；
3. 初步判断目标受众可能是哪些人群，并说明理由。
```

```text
【第 2 段｜思考与策略】
基于你刚才的分析（设计特点：【引用 Output A 设计特点】；
功能信息：【引用 Output A 功能列表】；受众：【引用 Output A 受众判断】），
以资深社交媒体营销策划的身份，为这款咖啡机构思至少 3 个不同切入角度的
推文创意。每个创意包含：
A. 15 字以内的标题或开场白；
B. 说明它如何打动你判断出的目标受众。
```

```text
【第 3 段｜行动与成果输出】
我采用第 2 个创意。请把它扩写成一条可直接发布的图文帖：
1. 标题 / 开场白；
2. 100–120 字正文，融入目标受众的痛点；
3. 2–3 个当前热门的中文标签；
4. 配图方案（1:1，简洁明快，突出咖啡品质感与现代家居的融合）；
   若不能直接生成图片，用文字描述构图。
```

说明：每段只做一件事，段的边界就是产物；每段开头引用上一段的具体产物，后一段才不会"忘了"前一段的结论。

## 常见坑

- 不要在一条提示词里塞 4 个不同性质的活。笔记的观察是：一条提示词塞太多任务，模型会"不听话"，拆开并用框架串起来才稳定。
- 不要让下游段"根据上文"续写。要粘贴具体引用占位（【引用 Output A 的…】），否则它会自己编一个上文。
- 不要拆成没有验收点的流水线。每段结尾留一句"输出后我确认，再进入下一段"，中间返工最便宜。
- 不要用拆解弥补需求不清。拆完每一段还是模糊，说明该先澄清，而不是继续切。
- 不要在换轮之间改需求却沿用旧产物。改了目标就从头重跑，混用会得到一份前后矛盾的东西。
- 不要给推理模型写"第一步 / 第二步"当思考指令。拆解是为了分离产物，不是为了规定它怎么想。
