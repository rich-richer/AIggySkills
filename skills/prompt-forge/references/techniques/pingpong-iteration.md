# 乒乓球迭代法（Ping-pong Iteration）

**什么时候读这个文件**：用户要做创作类任务（文案、命名、脚本、方案、插画）但需求说不清；或者一上手就想写一条"完美长提示词"。
**读完你会得到什么**：一套三轮内出可用稿的对话流程、一张把模糊感觉翻译成可执行方向词的替换表、以及什么时候该停手重开。

## 什么时候用

- 用户说"我想要那种……说不上来，你先写一版""帮我写个文案，要高级感"。
- 任务是创造性的：选题、命名、文案、脚本、活动方案、插画、视频脚本。
- 你已有一版初稿，但"觉得哪里不对"说不清。
- 用户正在把大量精力投到一条超长提示词上——这时该劝阻，先让模型出一版。
- 同一类创作反复出现，想把打乒乓的成果固化成模板（见第 6 步）。

## 怎么做

1. **投石问路（第 1 轮）**：只给目标 + 最少约束，明确要求"先出 1 版初稿，不用完美"。目的不是拿到好稿，而是拿到一个可批评的靶子。
2. **审稿只标 1–2 处**：读完初稿，圈出最不舒服的 1–2 个点，其余先不管。一次给 8 条意见，模型必然顾此失彼。
3. **把感觉翻译成方向**：每个不满换成一个可执行维度——语气（更冷/更暖）、节奏（更短句）、视角（去掉"我"）、密度（删修饰）、意象（增加一点忧郁的气息）。
4. **锁定不变量**：每轮固定加一句"除以上两处外，其他保持不变"。不加这句，模型会整体重写，把你满意的部分一起改掉。
5. **3–4 轮收束**：一般第 3 轮能到可用。超过 5 轮还在改同一个点，说明方向错了——回第 1 步重开一版，而不是继续微调。
6. **固化**：满意的稿 + 你实际给过的反馈，合成一条带示例的提示词（见 [RCARE](./rcare.md)），下次同类任务直接用模板起步。

具象化替换表（左列都是无效反馈）：

| 不要说 | 改说 |
|---|---|
| 更优美一点 / 更好看 | 增加一点忧郁的气息；提高对比度 |
| 更专业一点 | 换成行业术语，删掉感叹号，句子控制在 25 字内 |
| 更有创意 | 给 3 个反直觉的切入角度，不要"痛点 + 解决方案"这个结构 |
| 太长了 | 压到 120 字以内，只保留一个论点 |
| 语气不对 | 改成对同行说话，不要对客户说话 |
| 不吸引人 | 把开头第一句改成提问句 |
| 太干了 | 每个论点后加一个具体场景，不要加形容词 |

## 示例

差（一次问到位 + 无效反馈）：

```text
你是一位世界级文案大师，请运用 AIDA、PAS、FAB 等 12 种模型，
为新款智能咖啡机写一段 150 字的营销文案，风格活泼有趣，要吸引年轻人。
```

→ 结果通常是"既活泼又高级"的四平八稳文案。你没法指出哪里不对，只能说"再改改"，然后它再随机改一遍。

好（三轮乒乓）：

```text
【第 1 轮｜投石问路】
给一款能连 Wi-Fi、用 App 远程控制、能自定义口味的智能咖啡机写一段营销文案，
给年轻人看，150 字左右。先出 1 版初稿就好，不用完美。
```

```text
【第 2 轮｜只改两处】
第 2 段太像参数表。改两处，其他保持不变：
① 删掉所有参数数字，换成使用场景（比如早上还没清醒、手忙脚乱的那一分钟）；
② 结尾不要喊"快来购买"，改成一句朋友之间的推荐。
```

```text
【第 3 轮｜再收一次】
保留第 2 轮的结果。只做一处：把"智能便捷"换成一个具体动作，
比如"在电梯里点一下，到家就能喝"。
```

说明：三轮跑完的稿子，通常比那条"12 种模型"的长提示词更准——因为你每次只让模型猜一件事，而且把判据具象化了。

## 常见坑

- 不要在创作任务第一轮就写带角色、框架、多条约束的长提示词。复杂提示词像职场里的"微管理"，会扼杀创造力。
- 不要一次给一整页反馈。模型会各改一半，或者整体重写，最后比初稿更差。
- 不要用形容词当反馈。"更高级""再打磨"不是指令；要落到"删掉感叹号""换成短句"这种能动手的维度。
- 不要每轮都让它从头写。不加"其他保持不变"，好句子会被顺手改掉，几轮下来一直在打转。
- 不要在需要唯一正确答案的任务上用乒乓（抽取、翻译、格式转换）。那类任务一次把字段和规则给全，越快越准。
- 不要把乒乓当成反复抽卡。三轮没收敛就换方向重开，而不是把同一条提示词再发十遍。
