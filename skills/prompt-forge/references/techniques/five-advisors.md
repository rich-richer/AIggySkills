# 五顾问评审（Five Advisors Review）

**什么时候读这个文件**：你有一个已经成形的方案或计划需要被拆穿；或者你需要多角度意见，而不是一句"总体不错"。
**读完你会得到什么**：五个立场的定义与约束写法、可直接复制的评审提示词、以及如何自己合成结论（而不是让 AI 和稀泥）。

## 什么时候用

- 方案已经写出来了（预算、涨价、上线计划、组织调整），要压力测试。
- 决策代价高，你只想先听反对意见。
- 你自己已有倾向，需要有人从反面把你说服，或说服你放弃。
- 方案读起来"没毛病"——这往往说明没人从代价和执行角度看它。
- 要在多个方案里选，需要多维打分而不是单一喜好。

## 怎么做

1. **先澄清，再评审**。评审前确认：方案目标、约束（预算 / 时间 / 人力）、决策者是谁、什么算成功。信息不全时，五个顾问会各答各的想象。
2. **定死五个立场，写明"只站自己立场，不互相妥协"**：

| 顾问 | 只回答一个问题 | 考核它的产出 |
|---|---|---|
| 反驳者 | 这个方案最大的漏洞是什么 | 攻击点是否致命、是否有具体触发场景 |
| 本质派 | 这个问题 / 方案的底层逻辑是什么 | 是否回答了"真正在解决什么" |
| 扩张者 | 哪里可以放大价值 | 是否给了可执行的机会，不是空想 |
| 代价计算者 | 真实成本和风险是多少 | 是否算了隐性成本（人力、机会、维护） |
| 执行者 | 实际落地难度和关键障碍 | 是否指出第一步会卡在哪 |

3. **一人一段，禁止互相评论**。加一句"每位顾问不知道其他顾问的存在"。否则后四位会附和第一位。
4. **要求给证据和可执行建议**：每条意见写成"判断 + 依据 + 如果要改，改成什么"。只要判断不要依据的意见，事后无法采信。
5. **自己合成**。评审输出后不要再让 AI"综合出最优答案"——它会磨平冲突；你列出哪些意见互相冲突、你接受哪条、为什么。
6. **复杂决策可以加一轮"冲突清单"**：把五条意见再喂回去，要求它只列冲突点，不作裁决。

## 示例

完整可复制：

```text
# 第一步：先确认信息（信息不足时先问我，不要直接开始）
在评审前请确认你已理解：方案目标、约束（预算 / 时间 / 人力）、决策者、
以及我认为什么算"成功"。

# 第二步：五个独立顾问评审
请扮演 5 位立场完全独立的顾问，分别从以下角度审视我的方案。
每位顾问只站自己的立场，不互相妥协，也不知道其他顾问的存在。
- 反驳者：找出方案最大的漏洞。要具体到"在什么条件下会失败"。
- 本质派：挖掘这个问题 / 方案的底层逻辑。它真正在解决什么？有没有更根本的问法？
- 扩张者：找出可以放大价值的机会。给 2 个具体可执行的放大动作。
- 代价计算者：列出执行该方案的真实成本与风险，包括隐性成本
  （人力、机会成本、后续维护、组织摩擦），能估算的给数量级。
- 执行者：评估实际落地难度，指出最关键的一个障碍，以及第一周会卡在哪。

# 第三步：输出格式
Markdown 表格，列为：顾问 / 最尖锐的一条判断 / 依据 / 如果要改，改成什么。
表格后另起一段：列出五条意见之间互相冲突的地方（至少 2 条），不要给结论。

# 约束
- 每条判断不超过 80 字。
- 禁止写"总体来看方案不错"这类综合意见。
- 没有依据的判断请标注"（推测）"。
```

填好的示例（输入一行方案，输出缩略）：

输入：`知识付费社群年费从 599 元提到 799 元，理由是老用户续费率 68%，高于行业均值。`

| 顾问 | 判断 | 依据 | 改成什么 |
|---|---|---|---|
| 反驳者 | 高续费可能是低价筛选的结果，提价后会换一批人 | 68% 在 599 价位上常见于"低价囤课"人群 | 先做 100 人的 AB 测试，再全量 |
| 本质派 | 真正要解决的是"收入不足"还是"续费意愿被低估" | 若是收入不足，提价和砍成本要一起算 | 先算提价 20% 对 LTV 的敏感性 |
| 扩张者 | 老用户可做高价位分层产品 | 68% 续费率说明信任度足够支撑高价 SKU | 加一档 1999 元小班，保留 599 档 |
| 代价计算者 | 隐性成本是口碑与退款率 | 提价后的退款和差评会集中在公开社群 | 预留一次价格回调与补偿方案 |
| 执行者 | 卡在"同群不同价"的沟通 | 同一社群内两个价位共存必然被比较 | 提前定好老用户锁价期与统一话术 |

## 常见坑

- 不要省略"只站自己立场，不互相妥协"。不加这句，五位顾问会互相点赞，输出五段一样的"总体不错，建议优化"。
- 不要只给角色名不给判据。"反驳者"如果不写"具体到在什么条件下会失败"，它会给你一句"存在一定风险"。
- 不要让 AI 最后自己综合。五位立场冲突是设计目的，让模型调和等于把最有价值的信息磨平；合成由你做。
- 不要让五个都变成批评者。扩张者和执行者的提问方式是要机会、要路径，不是要漏洞。
- 不要把澄清步骤跳掉。方案参数不全时，评审会针对模型自己想象的方案展开。
- 不要用在有唯一正确答案的问题上。事实查询、计算题不需要五视角，需要验证。

## 出处

用户整理的五顾问评审提示词（工作区笔记 `prompt_library.txt` 开头第 1–8 行），原文用法为"先用提示词一澄清需求，再用提示词二多角度评审输出结果"；五个角色（反驳者 / 本质派 / 扩张者 / 代价计算者 / 执行者）的定义按笔记原文。
