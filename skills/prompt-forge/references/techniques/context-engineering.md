# 上下文工程（Context Engineering）

**什么时候读这个文件**：资料很多但模型抓错重点；长对话到后面开始忘；要把知识库接进任务；或者你以为"窗口够大就没问题"。
**读完你会得到什么**：最小高信号上下文的取舍规则、长文摆放位置与二次锚定写法、压缩与隔离的具体做法，以及一份可直接用的长文档问答骨架。

## 什么时候用

- 输入是长文档、多份资料、整个知识库的切片。
- 上下文窗口很大，但回答引用了中间那段无关内容，或漏掉最关键的一段。
- 多轮任务进行到第 10 轮后开始丢约束。
- 同一批资料要反复用于不同问题（成本与效果都敏感）。
- 要做子代理 / 检索 / 自动化的拆分，必须先决定"主上下文里留什么"。

## 怎么做

1. **最小高信号**：只留能改变输出的 token。逐段做删除测试——这段删掉，输出会变吗？不变就删。塞满窗口不会提升召回，只会稀释注意力："上下文窗口大就能解决召回"已被 context rot（上下文腐化）与 lost-in-the-middle（中间遗忘）证伪。
2. **位置**：长材料放前面，问题和指令放后面。不要写完指令再堆三万字原文。
3. **超过 1 万 token 时三重锚定**：① 开头要求模型先复述关键约束；② 结论必须锚定到具体章节或页码；③ 末尾再重复一次约束和引用要求。
4. **中间产物外置**：跨轮的东西写进文件（如 NOTES.md、中间稿），下一轮引用文件内容，不要指望对话记忆。
5. **压缩要有回查路径**：摘要 + 保留关键原文段落。只留摘要会丢可引用的细节；只留原文会挤爆上下文。
6. **隔离**：能先检索、先用子代理缩范围的，不要把整库塞进主上下文。子代理只回传"结论 + 引用位置 + 结构化字段"，不要回传长文——回传长文等于没隔离。
7. **原始材料优先**：能给原始数据、日志、档案，就不要只给别人加工过的结论或待填模板——二手结论会把模型的判断上限锁死在原作者那里（`./ambition-4d.md` 第 3、4 节）。
8. **常驻与按需分层**：每次都会加载的上下文（如项目级 CLAUDE.md）只放干活必知的内容——常用命令、架构决策、关键文件、风格约定，越短越好；其余用文件引用（`@路径`）、子目录说明或斜杠命令按需拉取。团队共享的放进版本库，个人偏好放本地文件。同一纠正第二次出现，就固化进常驻层（Boris Cherny 演讲）。

长文档问答骨架：

```text
# 输入
以下是 {{文档名}} 的第 {{N}} 页到第 {{M}} 页全文（约 {{X}} 千字）：
<document>
{{原文}}
</document>

# 指令（放在材料之后）
1. 先用 5 行以内复述：本任务的约束、我要的答案形式、以及你认为材料中
   与问题最相关的 3 个章节标题。
2. 然后回答：{{问题}}
3. 每个结论后标注来源：【{{文档名}}|第 X 页】，具体到你引用的那句话所在页。
4. 材料里没有的，写"资料中未找到"，不要用通用知识补。

# 结尾再确认（重复一次）
再次确认：所有结论必须能在上面的材料里找到对应句子；找不到的请明确标注。
```

## 示例

差（指令在前、材料在后、一次问完）：

```text
请总结下面这段材料的主要观点，并回答我的问题。
问题：这家公司 2025 年的三个主要风险是什么？
[粘贴 40 页 PDF 全文]
```

→ 结果往往从中间段落随便抓几句，页码对不上，或者干脆用行业常识编。

好（材料在前、指令在后、复述 + 锚定 + 末尾重申）：

```text
<document name="2025年年度报告.pdf">
[第 1–40 页全文]
</document>

# 任务
基于上面的年报，回答：该公司 2025 年的三个主要风险是什么？

# 规则
1. 先复述约束（3 行内）：本任务只看这份年报，不看外部信息。
2. 每条例出的风险必须直接引用原文，格式【2025年年度报告.pdf|第 X 页】。
3. 如果年报里只提到 2 条明确风险，就只写 2 条，第三条写"资料中未找到"，
   不要用行业常识凑满三条。
4. 最后再用一句话复述你的三条结论，方便我核对。

# 一句话提醒
所有结论必须能在上面的文档中找到原句，找不到就标注。
```

说明：材料位置、复述约束、页码锚定、末尾重复这四件事要一起用才有效；单独做一件通常没用——长上下文下模型的注意力会漂。

压缩示例：40 页年报 → 保留"风险因素"章节原文 + 董事会讨论摘要 500 字 + 财务三表关键行；其余章节只留目录。这比"全文摘要 800 字"更能回答具体问题，因为关键段落还在、页码可查。

## 常见坑

- 不要以为窗口大就等于记得住。长上下文里中间部分最容易被忽略；关键约束要放前后两端。
- 不要把一堆资料全贴进去再加一句"帮我总结"，也不要把指令写在最前面然后堆三万字材料。先筛、先检索、先缩范围，再进主上下文——这两种写法是长文档任务最常见的失效原因。
- 不要用对话记忆代替笔记。第 15 轮之后"我们前面说过的约束"基本不可靠；写进文件再引用。
- 不要压缩到只剩摘要还要求引用页码。摘要里没有页码，最后一定会编。
- 不要给子代理一个"总结这份报告"的任务然后收回 2000 字。子代理的价值是缩小上下文，回来的是结论和位置，不是另一篇文章。
- 长模板里不要随意改动稳定的前缀部分，固定的说明在前、每次变化的输入在后更省（各厂商缓存机制与计费需按其文档核对）。
