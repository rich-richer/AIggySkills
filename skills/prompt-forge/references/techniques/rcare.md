# RCARE + RICE：复杂任务的五要素骨架

**什么时候读这个文件**：任务有多个维度（受众、格式、边界、素材）要同时对齐；一条提示词要反复用；或者你总在同一个地方反复出错，需要定位改哪一段。
**读完你会得到什么**：RCARE 五要素内容清单、五步使用流程、一张"症状 → 改哪个要素"的诊断表，以及一条完整填好的可用提示词。

## 什么时候用

- 用户说"这个任务挺复杂，我要一条能反复用的提示词"。
- 输出反复在某一方面不合格（太长、跑题、语气不对、编数据），但不知道改哪里。
- 需要把"做什么"和"不许做什么"分开写清——这正是 RICE 不够用的典型场景。
- 要交给别人复用（同事 / 团队 / 自动化流程），结构必须自解释。
- 同一条提示词要同时约束多个目标（比如既限字数又要固定表格结构）。

## 怎么做

RCARE 相对 RICE 的实质差异只有一处：把笼统的"指令（Instruction）"拆成"目标（Aim）"和"规则（Rules）"两段。

| 要素 | 回答什么 | 常见错误 |
|---|---|---|
| 角色 Role | 用什么身份、什么视角说话 | 写"世界级专家"却不改变任何行为 |
| 上下文 Context | 基于什么事实和材料 | 写成与任务无关的自我介绍 |
| 目标 Aim | 做到什么程度、成功标准、子目标 | 只有"帮我写一份报告" |
| 规则 Rules | 边界、禁止项、字数、不能出现什么 | 和目标混在同一段里 |
| 示例 Example | 输出长什么样（片段 / 反例） | 只给一个例子导致照抄 |

五步使用流程（按顺序，别跳）：

1. **填初版**：五个要素各写 1–2 句，允许不完美。
2. **跑一次看输出**。
3. **诊断定位**：用下面的症状表判断是哪一段的问题。
4. **只改那一段**，再跑。
5. **循环 2–4 步**直到稳定，然后把稳定版存成模板。

症状 → 改哪个要素：

| 症状 | 先改 |
|---|---|
| 输出空泛、正确但没用 | 目标：把成功标准写成一个能判真假的句子 |
| 事实错、编数据、编页码 | 上下文：给原始材料，并要求引用（见[引用锚定](./citation-anchoring.md)） |
| 太长 / 太短 / 格式不对 | 规则 + 示例：给长度上限和一个格式片段 |
| 语气不像、读者不对 | 角色：写"对谁说话"，不是写"你多厉害" |
| 结构每次都不一样 | 示例：给结构片段，或用 [结构化输出](./structured-output.md) 的 schema |
| 只覆盖一部分需求 | 目标：把宏观目标拆成编号子目标 |

**RICE 什么时候够用**：RICE（角色 / 指令 / 上下文 / 示例）适合"基础或常规任务、追求快速构建"。任务多维度、需要精准控制时才升到 RCARE。也可以在 RCARE 内部嵌套 RICE：外层五段，内层在"上下文与目标"里按 RICE 的粒度展开细节。

## 示例

填好的完整 RCARE（可直接用，只换掉具体业务信息）：

```text
# 角色（Role）
你是一名给企业中层做培训的课程设计师，习惯把方法论落到可执行的动作上。

# 上下文（Context）
- 我是一家 200 人电商公司的培训负责人，下周要给 12 名新晋主管做一次 90 分钟
  线下培训，主题是"如何给下属做绩效反馈"。
- 学员画像：平均带 3–5 人，第一次当主管，普遍怕冲突，习惯说"整体不错，继续努力"。
- 已有素材：公司现行的绩效面谈表格，含 4 个维度——目标达成、协作、主动性、改进点。
- 时间限制：现场只有 90 分钟，其中要留 30 分钟做角色演练。

# 目标（Aim）
产出一份 90 分钟培训的逐段流程，满足：
1. 每个环节标注时长，总时长不超过 90 分钟；
2. 至少 1 个环节直接使用公司的 4 维表格；
3. 学员课后能独立完成一次 15 分钟的绩效反馈对话；
4. 有 30 分钟用于两两演练，并给出演练用的具体案例卡。

# 规则（Rules）
- 用 Markdown 表格输出流程，列为：时间 / 环节名称 / 讲师做什么 / 学员做什么 / 产出物。
- 不写"提升沟通能力"这类目标口号，每个环节要有可观察的动作或产出物。
- 演练案例必须写完整对话背景（下属表现、数据、主管的顾虑），不要只写"设计一个案例"。
- 全文不超过 1200 字，不要引言和总结段。

# 示例（Example）
时间 | 环节名称 | 讲师做什么 | 学员做什么 | 产出物
0–5min | 开场定调 | 讲一个"反馈说错话"的真实翻车案例 | 听 | 无
5–25min | 四维表格拆解 | 逐维度讲判定标准，每维举 1 个反例 | 对照自己的下属填表 | 填好的表格
...
```

说明：角色只写"行为取向"，不写"世界级专家"；上下文给了受众、素材、时间三个能改变输出的硬约束；目标拆成 4 个编号子目标，每个都能判真假；规则承担了长度、格式、禁语全部需求；示例给的是**一行表格片段**而不是完整答案——给片段是为了定结构，不是让它抄内容。

## 常见坑

- 不要把角色写成"你是世界顶级专家"。它只改语气和视角，不改事实准确度；需要准确性就靠上下文 + 引用锚定，不靠头衔。
- 不要把上下文写成"我是谁、我很忙、这件事很重要"。上下文的唯一判据：这段信息能不能改变输出。
- 不要把目标和规则混在一段。目标回答"做到什么程度"，规则回答"不许做什么"；混写以后模型通常只执行前面那一半。
- 不要只给一个示例。单一示例会让模型照抄表层特征；给 1 个正例 + 1 个"这不算合格"的反例更有效。
- 不要死守五段顺序到底。长材料放前面、任务和规则放后面；RCARE 是内容清单，不是排版顺序。
- 不要在诊断时一次改五段。一次只改一段，你才知道是哪段起的作用。
