# 雄心四维度：速度 / 高度 / 深度 / 范围（Ambition 4D）

**什么时候读这个文件**：任务的成败取决于"要做的事情本身有没有定对"，而不只是提示词结构是否齐全；用户请求的是一个交付物名词（汇报、报告、方案、文案、PPT）；或者你在体检时发现提示词结构合格，但任务定得太低、太浅、视角太窄。
**读完你会得到什么**：名词换动词的执行规则（什么时候必须做、什么时候不加）、高度 / 深度 / 范围三个维度各自的写法和判据、一段可直接复制的"深度元提示词"，以及"目标定得高"和"逃生口"之间的边界。

> 定位：`rubric.md` 的十项检查测的是**结构卫生**；本卡管的是**任务定义的雄心**——rubric 免责声明里说的"任务本身没想清楚"，就由这里补。两者互补，不互相替代。

## 1. 四个维度一句话

| 维度 | 一句话 | 在本 skill 里落在哪 |
|---|---|---|
| 速度 Speed | 同样的活更快做完。只是起点，大多数人停在这里 | 不单独处理 |
| 高度 Altitude | 往上追问一层：做这件事到底为了什么、做完后要发生什么 | 采访 `I-G1` + 名词换动词 + `I-D1` |
| 深度 Depth | 像领域顶尖专家那样做：一手材料、专业方法与工具、独立验证 | 组装阶段 + 深度元提示词 |
| 范围 Range | 借用多个其他领域的方法，并安排一方专门挑刺 | `I-D2` + 组装阶段 |

合用口诀：**高度定目标，范围借方法，深度做扎实。**

## 2. 名词换动词（高度与范围的共同入口）

**做法**：把用户要的交付物名词，改写成一句动词句：

```text
在【时间／场合】内，让【谁】【看清／相信／决定／去做】【什么】。
```

例：`做一份季度汇报 PPT` → `在 30 分钟内，让管理层看清本季度增长的因果，并决定下季度的钱和人头投到哪里。`

动词化之后有两个直接收益：① 目标从"形式"变成"结果"，可以据此写出可判定的成功标准（对应 `rubric.md` 第 1 项）；② 动词能指向"哪些行当天天在做这个动作"，范围维度就有了借方法的对象。

### 2.1 什么时候必须执行

满足任意一条即执行：

1. **请求核心是交付物名词，且要给别人看**：汇报、报告、方案、PPT、文案、邮件、周报、复盘、BP、PRD、落地页、海报的文案部分。
2. **用户用形容词代替标准**：「专业一点」「让人想买」「有说服力」「高级感」。
3. **任务与开会、汇报、决策相关**：这是原文给出的信号，此类任务最容易交出"形式完整但没用"的东西。
4. **需要借跨领域方法时**：先有动词，才能问"哪些行当天天在做这个动作"。
5. **诊断模式里，被体检提示词的任务句是"名词 + 形容词"**：如「写个好一点的产品文案」。

### 2.2 什么时候确认不需要（不加）

1. **输出给程序消费**：`extraction`、`automation` 节点。动作已经固定（分类、抽取、打标），动词化不改变输出，只多耗 token。
2. **任务本身已是"动作 + 对象 + 验收"**：「修复 issue #123 并让测试通过」「把这段翻成中文」、`procedure` 类操作与排错。
3. **学习解释类**（`learning`）：目标就是"让我理解"，已经是动词。
4. **图像视频类**（`image-video`）：提示词正文要的是视觉描述，动词句不进正文（采访时可用来定用途，但不写入）。
5. **第 0 步判定为"直接干活"的随手请求**：不走提示词流程。

### 2.3 拿不准时：问一句再定

```text
这份【交付物】交出去之后，你希望看的人做什么？
```

- 答得出具体动作或决定 → 执行动词化。
- 答"存档／走流程／交差" → 不加，只按格式要求写。

### 2.4 形式被指定时

用户明确说格式是规定的（老板给的模板、平台固定版式）→ **照样写动词句**作为目标首句，但**不进入**下面高度第 3 步"质疑形式本身"。

### 2.5 写进哪里

- 采访：不新增问题，复用 `I-G1` 的回答改写成动词句；拿不准时用 2.3 的问题替换 `I-G1` 的追问。
- 确认：第 3 轮 `I-F1` 复述时把动词句一并给用户确认。
- 组装：动词句作为提示词"目标"段的首句；模式骨架里已有目标段的（如 `report` 的"谁的决策，什么时候做"、`creative` 的"一句话目标"），直接写进去，不另起一段。
- 自检：`rubric.md` 第 7 节"雄心检查"第 1 项。

## 3. 高度（Altitude）

**核心问题**：你希望接下来发生什么？也就是"目标之上的目标"是什么。例：从"让 Claude 修某个崩溃"升级为"让 Claude 保持这些应用不崩溃"。

**三步升级**（以季度汇报为例，按任务需要停在任意一步）：

1. **喂原始数据，要故事**：尽可能多给数据，不给待填模板。写法：`告诉我本季度变了什么、为什么变、我们该怎么应对。`
2. **要决策**：`基于你掌握的全部信息，找出最紧迫的 3 个决策，并为每个决策给出备选方向及支持／反对理由。`
3. **质疑形式本身**：说明交付物存在的真实意义（如"让管理层尽早发现问题、把钱和人调到对的地方"），请模型设计比现有形式更好的机制，用历史数据检验它能否更早发现问题，并提出与现流程并行试跑一个周期。

**适用与限制**：
- 最适合有明确最终结果的任务；对纯创意任务效果弱一些。
- 信号：任务里涉及开会。
- 有上限：「去赚钱」这类过于空泛的目标，对多数业务在 2026 年仍不可执行。高度要高到"结果"，不要高到"愿景"。
- 拉高度能形成把人从重复循环里解放出来的长期工作流，但要先搭环境：例如"保持不崩溃"之前，先让模型能拿到崩溃报告、把版本号对应到 commit、能在目标系统上复现与验证修复。没有这些权限，高度只是一句空话（对应 `modes/agentic.md` 的权限段）。

## 4. 深度（Depth）

**定义**：按该领域顶尖从业者的工具、方法和知识去做，推到专家也能从结果里学到东西为止。

**判据**：要的是**更深**的版本，不是**更大、更长**的版本。

**五个技巧**：

1. **用顶尖从业者的工具，不只是他们的词汇**：只说"专业一点"，模型往往只换词不换方法。它默认用 markdown 表格时，推它用数据库、统计模型。用户不必知道专家用什么，模型通常知道。
2. **设一个看似不合理的高目标，当作合理的来提**：如页面加载从 10 秒压到 200 毫秒。模型说做不到时，坚持这是可解的，让它继续找方法（边界见第 6 节）。
3. **挑战用户自己的假设**：给原始数据，让它对抗性检验。写法：`我们认为流失是新手引导环节的问题，请尝试从原始数据中复现这个结论。`
4. **产出新知识**：让它找盲区。写法：`用我们的日志建一个能复现过去一年的客户模拟，找出最早的、此前未知的流失信号，并在你没见过的数据上证明它能预测结果。`
5. **用外部裁判，不让模型自评**：最好是模型能自己运行、立刻拿到反馈的工具（测试、脚本、截图对比）。与 `self-critique.md` 的"验证器优于投票器"一致。

**深度元提示词**（可直接复制；用法：把用户原始提示词贴在它后面 → 拿到重写版 → 人工审一遍 → 再用重写版执行）：

```text
我想要的是一个更深入的版本，而不是一个更大的版本。
在重写任务之前，请先完成以下工作：

1. 说明在这个领域，一位顶尖专业人士会采取哪些我尚未提出的做法；
2. 指出他们会从哪些最原始的数据或材料入手，而不是使用那些已经经过加工、整理和解读的信息；
3. 列出他们会采用的具体方法和工具；
4. 说明除了你和我之外，还有什么能够独立证明最终结果是正确的。

最后，请根据以上分析重新编写我的提示词，明确要求模型按照这些方式开展工作。

【我的原始提示词】
{{原始提示词}}
```

## 5. 范围（Range）

**定义**：用多个领域的视角看同一件工作。以前组一支跨领域队伍不划算，现在多智能体（子智能体、并行线程、编排器）让它变得便宜。类比：抢劫片前 30 分钟都在组一支各有所长的队伍。

**判据**：动词已经写出；点名至少两个可借鉴的领域，每个领域对应一个真实子问题和一个具体方法；有一方负责反向审查。

**组队示例**（季度汇报）：
- 数据分析师的归因模型 → 解释"为什么变"。
- 调查记者挖故事的手法 → 找出数据背后的真实事件。
- 顶尖编辑的表达结构 → 30 分钟内讲清楚。
- 若要现场演示，再加动效与音频设计。
- 红队：做空机构与法务会计的研究方法 → 反向审查数字和叙事。

**禁忌：借方法，不扮角色。** 不要让模型模仿某类人的语气写稿（"用做空者的口吻点评"），那只会让文字阴阳怪气，结果并不更好；要让它去**做**那类人研究时实际会做的事。

- ❌ `你是一名做空者，用做空者的口吻点评这份汇报。`
- ✅ `调用做空者研究一个标的时的具体方法（如核对收入确认口径、追踪应收与现金流背离），各自解决我汇报里的一个真实问题，并说明每个方法解决了哪个问题。`

这条与 `anti-patterns.md` 第 3 条（persona 背事实）、第 17 条（模仿语气代替借方法）配套。

**前提**：模型需要能装软件、能拿到相关数据的环境（MCP 连接器或其他方式）。纯聊天环境里，范围维度只能停在"给出方法清单"，要在交付物的「用法」里说明这一点。

**范围模板**：

```text
这件事的动词是：{{动词句}}。
请组建一个跨领域小组：
- {{领域A}}：负责 {{子问题A}}，使用 {{方法A}}；
- {{领域B}}：负责 {{子问题B}}，使用 {{方法B}}；
- 红队 {{领域C}}：用其研究方法做反向审查，只找问题，不改写。
不要模仿任何角色的语气，只使用他们的方法；最后列出每个方法解决了哪个问题。
```

## 6. 与本 skill 铁律的边界

1. **"目标定得高"≠"不许报告失败"**：坚持可解，指的是**方法上**换路子继续尝试；遇到**事实缺失**，仍按 `rubric.md` 第 4 项写逃生口（「资料未覆盖，标暂缺」）。两句话要同时出现在提示词里，不能只留一句。
2. **四维度作用在采访与任务定义上，不往正文堆段落**：遵守"能 200 字说清不写 800 字"。正文里通常只多出一句动词目标、一两行方法清单、一行验证方式。
3. **一次只开需要的维度**：默认组合见 `index.md`。抽取、自动化、图像视频、操作类默认不开。

## 7. 常见坑

1. 把动词句写成口号（"赋能业务增长"）——必须有"谁、在什么时间内、做什么决定"。
2. 对抽取或自动化节点做动词化——徒增 token，不改变输出。
3. 用"你是顶级专家"代替深度——换的是词，不是方法。
4. 用户指定了模板还去质疑形式——只写动词目标，不进高度第 3 步。
5. 只写"坚持做到"不写逃生口——会把模型逼去编造。
6. 让模型给自己打分当作验证——深度第 5 条要求外部裁判。
