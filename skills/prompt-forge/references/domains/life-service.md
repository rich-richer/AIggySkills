# 生活服务（Life Services）

**什么时候读这个文件**：用户要处理生活里的事——出行行程、搬家装修、家政母婴、婚庆、宠物、办事流程、服务商比价。
**读完你会得到**：生活类需求必须问的 7 个参数、3 种交付骨架、比价与安全的边界，以及一个可直接用的家庭出行行程提示词。
**分工**：通用操作步骤（办事流程类）见 `../modes/procedure.md`；合同与维权问题转 `./legal.md`；健康相关内容转 `./health.md`。

## 什么时候用

- 用户会说：「帮我排个三天两夜的行程」「搬家要注意什么」「装修怎么比价」「这个套餐值不值」。
- 用户带着具体约束（预算、老人小孩、宠物、时间窗），要的是能照着做的清单，不是攻略合集。
- 内容涉及价格、库存、服务商资质——这些会过期，必须提示当日核实。
- 用户要的是「决定」，但信息来自平台评价与商家说法，真假混杂。

## 行业参数

| 维度 | 必须问到 | 用户不答时的默认 | 采访编号 |
|---|---|---|---|
| 场景、同行人与预算 | 几个人、有无老人小孩宠物、总预算与人均、能否超支 | 2 名成人，给区间、不接受超支 | `I-G1` / `I-G2` |
| 时间与地点 | 日期、天数、城市、出发地与交通方式 | 周末 2 天，市内/近郊 | `I-G1` |
| 硬约束 | 忌口、过敏、行动不便、必须打卡的点 | 无特殊约束，节奏中等 | `I-G3` |
| 决策标准 | 价格 / 口碑 / 距离 / 售后的优先级 | 价格与距离优先，口碑次之 | `I-P1` |
| 服务方信息 | 是自选商家还是平台推荐、有无合同 | 平台下单，有服务协议 | `I-G5` |
| 风险偏好 | 愿不愿意冒险（跟团/自由行、网红店/老店） | 保守，优先稳妥 | `I-G2` |

## 常用体裁 × 3

### 1. 行程规划（家庭/朋友出行）

```
【总体】{{天数}}、{{同行人}}、总预算 {{}}、节奏 {{紧凑/适中/宽松}}。
【每日安排】第 {{N}} 天：时段 | 地点 | 交通方式与耗时 | 预算 | 备注（预约/闭馆/排队）。
【缓冲】每天留 {{1–2}} 小时机动；标注哪些点可砍。
【吃】每餐给 {{2}} 个选择（价位 + 步行距离），含提前预约提示。
【应急】天气预案、就近医院、返程末班时间。
```

适合谁：带家人出行、怕排太满或漏预约的人；核心是缓冲与备选，不是打卡数量。

### 2. 服务商比价表（搬家/家政/维修/婚庆）

```
【维度与权重】价格 {{40%}}、口碑 {{25%}}、响应速度 {{20%}}、合同条款 {{15%}}。
【比价表】商家 | 报价（含什么/不含什么）| 时长 | 加价规则 | 售后 | 风险点。
【关键问句】问商家的 {{5–8}} 个问题（是否含搬运、楼层费、材料费、损坏怎么赔）。
【决策建议】按权重算分，并说明哪一项可能被低报价隐藏。
【签约要点】必须写进合同的 3 条（价格封顶、损坏赔偿、违约与改期）。
```

适合谁：第一次买大额生活服务、怕被二次加价的人。

### 3. 办事清单 SOP（证件/过户/入学/报销）

```
【前置材料】必须带的 {{}}；复印件份数与有效期要求。
【步骤】编号步骤：去哪 → 办什么 → 需要多久 → 常见退回原因。
【时间窗】办理时段、预约方式、法定时限。
【失败兜底】材料不齐怎么办、能否代办、投诉/咨询渠道。
【提醒】涉及费用与政策口径的，标注「以受理机构当日告知为准」。
```

适合谁：要跑一趟就办成、不想来回折腾的人。

## 术语与合规边界

**必用术语（首次出现给中英对照）**

- 人均预算、淡旺季（peak/off season）、自由行 vs 跟团、行程缓冲（buffer）。
- 订金与违约金、服务协议（service agreement）、履约时效、二次加价。
- 评价可信度（注意刷评）、应急联系人、责任划分（RACI）。
- 无障碍设施（accessibility）、适老与儿童友好。

**边界与合规**

- **价格与库存会变动**：所有报价、票价、房态标注「需当日核实」，不给过期承诺。
- **不构成法律/保险/金融建议**：押金纠纷、保险理赔、装修合同争议转 `./legal.md`；保险产品与理财决策转 `./finance.md`，只给自查清单。
- 安全红线：燃气、电路、高空作业、拆改承重墙必须持证与报批，不提供 DIY 指导；涉及儿童/老人/宠物出行需单独列注意事项。
- 隐私：行程单、住址、电话、身份证号脱敏后再上传或分享；不推荐无资质的「熟人价」服务，不鼓励绕过平台合同私下交易。
- 涉及医疗、心理、康复内容转 `./health.md`，不在本文件给建议。

## 填好的示例

场景：带 60 岁父母和 6 岁孩子在杭州玩 3 天 2 夜。可直接改城市使用。

```
你帮我排一份杭州 3 天 2 夜的行程，同行是我（35 岁）、父母（60 岁，父亲膝盖不太好，不能久站）、孩子（6 岁）。

## 约束
- 时间：周五下午 3 点高铁到杭州东，周日下午 5 点返程。
- 预算：一家 4 口总预算 6000 元（含住宿 2 晚、门票、吃饭、市内交通），可以略超 10%。
- 节奏：一天最多 2 个主要景点，午饭后必须回酒店休息 1.5 小时。
- 硬约束：父亲不爬长台阶、不排超过 30 分钟的队；孩子下午 4 点后容易情绪崩；我对海鲜过敏。
- 交通：全程打车或地铁，不租车。

## 你要产出
1. 每日时间表：时段 / 地点 / 交通方式与大致耗时 / 门票与人均花费 / 备注（预约、闭馆日、无障碍通道）。
2. 住宿建议 2 个：位置优先（离地铁近、有电梯），给价格区间，不要指定具体酒店品牌。
3. 每天 1–2 个「可砍掉的点」和 1 个备选（下雨时去哪）。
4. 餐厅：每餐 2 个选择，写明是否适合孩子与过敏者、是否需要提前订。
5. 应急信息清单：最近的医院（类型即可，不要具体科室电话）、返程末班车时间、雨天备案。
6. 需要我提前预约/购票的事项清单（按提前几天排序）。

## 边界
- 门票价、开放时间、预约规则都可能变，全部标注「需出行前 1 天核实」，不要给确定承诺。
- 不给任何医疗建议（父亲膝盖不适只写「减少台阶、预留休息」这类安排层面提示）。
- 不推荐具体商家与酒店品牌，只给位置与类型建议，避免变成广告。
- 预算按区间与总计给，允许我替换项目；总强度不得超过「一天 2 景点 + 午后休息」。
- 格式：Markdown 表格；一天一张表；全文 ≤1000 字；中文。
```

> 这段为什么这样写：把体力限制（台阶、排队、孩子情绪曲线）写成硬约束，行程才不会变成「景点清单」；强制「可砍掉的点 + 雨天备选 + 预约清单」是让行程落地而不是好看；价格与开放时间统一标「出行前核实」，避免用户按过期信息出行。
> 换模型：推理模型给约束与边界即可；小模型需要固定表头与一行填好的示例，否则会写成通用攻略。

## 常见坑

1. 不给同行人与体力约束 → 排出来的行程老人小孩走不动；先写「不能做什么」。
2. 行程塞满没有缓冲 → 一延误全乱；每天留 1–2 小时机动并标可砍项。
3. 让 AI 报准确票价/房态 → 信息很快过期；一律标「当日核实」。
4. 比价只看总价 → 忽略加价规则与售后；按「含什么/不含什么」逐项对齐，大额服务不签合同私下交易出问题没依据。
5. 涉及押金/理赔/装修争议仍让 AI 给结论 → 转 `./legal.md` 的思路，只做事实梳理。
