# 教培与课程交付（Education & Training）

**什么时候读这个文件**：用户要做课——课程大纲、教案、讲师手册、训练营 SOP、招生文案、培训评估，或给企业/家长/学员写教学类内容。
**读完你会得到**：教培场景必须锁死的 8 个参数、3 种主力体裁骨架、教学目标可观测化的写法、广告与未成年人合规红线，以及一个填好的训练营大纲提示词。
**分工**：内容骨架（创造类、学习类）见 `../modes/creative.md`、`../modes/learning.md`。这里只写「教培这个行业特有」的教学法与合规。

## 什么时候用

- 用户会说：「写个课程大纲」「帮我设计 8 次课」「写讲师手册/逐字稿」「招生文案怎么写」「训练营怎么排」。
- 用户在卖课或要交付培训：有学员、有课时、有交付物，需要能直接上课的东西。
- 企业内训场景：要写给 HR 看的方案，同时要能交给讲师执行。
- 用户只给了「主题」（比如「AI 办公」）没给学员画像——这是教培最常见的坏输入，必须先问。

## 行业参数

| 维度 | 必须问到 | 用户不答时的默认 | 采访编号 |
|---|---|---|---|
| 学员画像 | 年龄、基础、身份（员工/家长/学生/自由职业）、动机 | 25–40 岁职场人，零基础 | `I-L1` |
| 教学目标 | 学完能用什么动作完成什么任务（可观测） | 能独立完成 1 个实操任务 | `I-L2` |
| 课时与班型 | 几次课、每次多久、线上/线下、人数、有无助教 | 线上 60 分钟 × 6 次，40 人以内 | `I-G1` |
| 评估方式 | 作业 / 测验 / 实操 / 结业项目，谁批改 | 每次课 1 个可交付作业 + 结业项目 | `I-L2` |
| 交付载体 | 大纲 / 逐字稿 / PPT / 学员手册 / 讲师手册 | 大纲 + 讲师要点，不出逐字稿 | `I-G4` |
| 合规敏感度 | 是否 K12 学科类、是否承诺效果、是否用学员案例 | 不承诺效果、不用真实学员案例 | `I-G3` |
| 商业目标 | 招生 / 续报 / 企业采购 / 结业率 | 交付质量优先，转化次之 | `I-G1` |
| 时效与版本 | 内容涉及的工具/政策版本、更新时间 | 标注「以最新版本为准」 | `I-R1` |

## 常用体裁 × 3

### 1. 课程大纲（Course Outline）

```
【课程名】{{面向谁 + 解决什么问题 + 学完得到什么}}（不用「赋能/精通/速成」）。
【学员画像】{{基础/身份/痛点}}；不适合谁：{{明确说明}}。
【教学目标】学完能：{{3–5 条可观测动作}}；验收方式：{{作业/结业项目}}。
【课次表】第 {{N}} 次｜主题｜{{3–4}} 个知识点｜课堂练习｜课后作业｜对应目标。
【材料与工具】{{软件/模板/案例包/预习材料}}。
【评估】形成性：{{每次作业怎么批}}；终结性：{{结业标准}}。
```

适合谁：课程产品经理、训练营主讲、企业内训负责人；也是招生页与讲师排期的上游依赖。

### 2. 教案 / 讲师手册（Lesson Plan）

```
【本次目标】{{1–2 条}}，对应大纲第 {{N}} 次。
【时间轴】导入 {{5′}} → 讲解 {{20′}} → 示范 {{10′}} → 学员练习 {{15′}} → 点评 {{5′}} → 总结 {{5′}}。
【讲解要点】每点：一句话结论 + 一个正例 + 一个反例 + 学员最常犯的错。
【示范脚本】讲师要做的动作，逐步写；每步说清「为什么这样点」。
【练习设计】任务描述 + 判断标准 + 卡住时的降级版（简单一档）。
【助教分工】谁巡场、谁答疑、谁记录高频问题。
```

适合谁：新讲师上手、老讲师标准化交付、连锁机构统一教学质量。

### 3. 招生 / 续报文案（Enrollment Copy）

```
【写给谁】{{画像 + 此刻的具体处境}}。
【他们卡在哪】{{1–2}} 个具体场景（不是「缺乏认知」这类空话）。
【学完的变化】用「能做出什么」描述，不用「能力提升」。
【凭什么信你】{{讲师可核实的经历/课程结构/往期作业样例}}；不编造学员成绩。
【风险反转】{{试听/退款/不满意怎么办}}。
【行动】{{下一步动作 + 截止时间 + 成本}}。
```

适合谁：需要卖课但不想踩广告法的人；文案的合规性比文采重要得多。

## 术语与合规边界

**必用术语（首次出现给中英对照）**

- 教学目标（learning objective）：可观测的行为动词——「能写出 3 条合格标题」，不写「了解/掌握」。
- 布鲁姆目标分类（Bloom's Taxonomy）：记忆 / 理解 / 应用 / 分析 / 评价 / 创造，用来定难度梯度。
- 形成性评价（formative assessment）vs 终结性评价（summative assessment）。
- 翻转课堂（flipped classroom）、项目式学习（PBL, Project-Based Learning）。
- 讲师手册（facilitator guide）、学员手册（participant workbook）、训后转化（transfer）。
- 完课率、续报率、到课率、净推荐值（NPS）——教培机构的四个常用运营指标。

**合规红线（必须写进提示词）**

- **不得对升学、考试结果作保证性承诺**：禁用「保过」「提分 X 分」「包就业」「学完月入 X」等表述。
- **不得使用绝对化用语**（「最权威」「第一」「国家级」这类，具体以现行《广告法》文本为准）。
- **学员案例必须是真实且获授权的**，否则写成「示例场景」并注明虚构；不得编造学员成绩、就业去向、师资金牌履历。
- **未成年人**：涉及 K12 与未成年人的招生、信息收集，需监护人授权；广告与课程内容遵守未成年人保护相关规定。
- **学科类培训**：义务教育阶段学科类培训受「双减」政策严格限制，业务范围、资质与广告要求以当地最新规定为准（**待核实**）。
- **特殊资质类培训**（发证、职业资格、医疗健康、金融投教）：先确认机构有无资质，没有就不写「可发证/可就业」；涉及医疗、金融内容时分别叠加 `./health.md`、`./finance.md` 的边界。
- 涉及工具/平台操作的课程，写明「以官方最新版本为准」，不把旧版界面截图当永久依据。

## 填好的示例

场景：给一家 200 人的公司设计「AI 办公效率」内训，8 次课、每次 60 分钟、线上。可替换数字直接用。

```
你担任课程设计顾问。先按下面的约束产出大纲，我确认后再逐次写教案。

## 学员与企业
- 学员：市场部 25 人 + 行政 10 人，25–40 岁，能日常用微信/Office，80% 没用过 AI 工具写东西。
- 企业方诉求：3 个月内，市场部能独立用 AI 产出初稿（文案/活动方案），行政能自动化整理会议纪要。
- 硬约束：线上授课，每次 60 分钟，每周 1 次，共 8 次；企业不允许用付费工具之外的任何外部账号；每次课必须留 15 分钟练习。

## 你要交付
1. 8 次课的课次表：主题 / 3–4 个知识点 / 课堂练习 / 课后作业 / 对应哪个教学目标。
2. 教学目标写成可观测动作（「能写出 3 条含受众与场景的提示词」，不要写「了解提示词」）。
3. 每次课的评估方式：谁来批、按什么标准算通过。
4. 结业项目：一个真实工作任务（市场部：1 篇活动方案 + 3 条社媒文案；行政：1 套会议纪要模板）。
5. 讲师注意事项：哪几次课学员最容易放弃、卡点在哪、降级版练习怎么做。

## 边界
- 不承诺「提效 X 倍」「学完立刻省一半时间」这类效果承诺，一律改成可验收的作业标准。
- 涉及工具功能，写「以官方最新版本为准」；不确定的功能不要写进大纲。
- 不使用真实员工姓名与真实客户案例，示例统一写「示例场景」。
- 学员作业里可能出现的客户信息，教一次脱敏规则（把客户名换成「A 客户」）。
- 本课程不涉及学科培训，也不发任何证书；如果企业要求证书，请提示我确认合规后再写。

## 格式
Markdown 表格输出课次表；中文；术语首次出现给中英对照（如「检索练习（retrieval practice）」）。
```

> 这段为什么这样写：先锁「企业方诉求 + 硬约束 + 每次必须留练习」，大纲才不会变成知识目录；教学目标强制可观测动作是教培最容易翻车的地方；边界里把「效果承诺」「证书」「客户信息」三件事提前堵住，避免课程做完才发现宣传口径违规。
> 换模型：Gemini 4 建议在提示词里补 1 个「合格课次表长什么样」的短示例；推理模型（GPT-6 系）删掉「先出大纲再写教案」的分步指令，直接给最终目标和边界。

## 常见坑

1. 教学目标写「了解/掌握」→ 无法评估也无法排课；全部换成「能写出/能做出/能判断」。
2. 课次排满讲解、不留练习 → 成人学习留存极低；每次课至少 1/4 时间是练习。
3. 招生文案承诺效果或提分 → 踩广告法；改成「学完能交付什么」。
4. 编造学员案例与讲师履历 → 一条假案例可以毁掉整个课程口碑；没有就写「示例」，或干脆不写。
5. 一次让 AI 生成「大纲 + 逐字稿 + 招生页 + PPT 文案」→ 质量全面下降；按「大纲 → 教案 → 文案」拆三轮（李厂长《15分钟学会提示词9大秘籍》秘籍 8）。
6. 忽略降级版练习 → 班里 20% 跟不上的学员会拖垮完课率；每个练习准备一个更简单的版本。
