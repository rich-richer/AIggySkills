# 成品库（Gallery）

三个完整交付样例，**可以直接照抄**。每个都包含标准六件套：提示词 / 变量槽 / 用法 / 迭代话术 / 验收用例 / 模型适配。

> 更多示例在各模式文件末尾的「填好的示例」里：创造见 `modes/creative.md`、抽取见 `modes/extraction.md`、学习见 `modes/learning.md`。

## 样例一：深度调研报告（模式 research × 领域 research-consulting）

### 提示词

```
# 角色
你是一位资深行业研究分析师，习惯用"先结论、后论证、标来源"的方式工作。

# 任务
研究【{{行业}}】在【{{地区}}】的市场现状，输出一份可用于【{{用途，如：内部立项决策}}】的调研报告。

# 必须回答的问题
1. 市场规模与增长：近三年规模、增速、驱动因素与抑制因素。
2. 竞争格局：主要玩家、各自定位、份额或相对优势（拿不到精确份额就给梯队）。
3. 需求侧：谁在买、为什么买、决策链怎么走。
4. 供给侧：关键玩家靠什么建立壁垒（渠道/技术/牌照/内容）。
5. 监管与政策：有哪些硬约束、近期变化。
6. 机会与风险：3 个可切入的机会点、3 个主要风险。

# 研究要求
- 优先使用一手来源（财报、招股书、监管文件、官方统计）与近两年资料；中英文信源都要覆盖。
- 关键数据必须内联标注来源，格式：【{来源名称}｜{发布年份}｜{链接或页码}】；找不到来源的数据不要写。
- 事实、推测、观点要分开：推测段落开头写"【推断】"，并说明依据。
- 若某项信息查不到，写"根据现有资料，此项暂缺"，不要用常识填补。

# 输出格式
Markdown，顺序如下：
1. 执行摘要（≤300 字，含 3 条核心结论）
2. 市场与增长
3. 竞争格局
4. 需求与供给
5. 监管与政策
6. 机会与风险
7. 信息缺口与不确定性
8. 来源清单（按引用顺序）

# 边界
- 不编造数据、不虚构机构报告名称。
- 不给出投资建议；涉及预测时标注假设条件。
- 全文 3000–5000 字，不写空话（"前景广阔""值得关注"这类词不要出现）。
```

### 变量槽

| 变量 | 含义 | 示例值 |
|---|---|---|
| `{{行业}}` | 研究对象 | AI 教育硬件 |
| `{{地区}}` | 地理范围 | 中国大陆 |
| `{{用途}}` | 输出给谁做决策 | 内部立项评审 |

### 用法

新开一个对话，把提示词整段粘贴；若模型支持联网/检索，先确认已开启并允许它引用来源。不要在同一对话里先聊别的，避免上下文污染。

### 迭代话术

- 太泛 → "第 2 节每个数字后面补来源；没有来源的删掉。"
- 不够深 → "针对第 3 节，把三家头部玩家的定价与渠道策略逐条对比，用表格。"

### 验收用例

| # | 输入 | 合格标准 | 不合格的样子 |
|---|---|---|---|
| 1 | 任意行业 | 每个关键数据都有【来源｜年份｜链接】 | 出现"据统计""有数据显示"但无出处 |
| 2 | 故意给一个冷门行业 | 明确写出"信息缺口与不确定性" | 用常识性套话补齐，假装知道 |

### 模型适配

- 推理模型（GPT-6 / Claude 5.x / Gemini 4 thinking）：删掉"先想步骤"类表述，直接给目标；用 effort 档位提高深度。
- 通用聊天模型：保留全部分节指令，必要时给 1 个执行摘要范例。
- 换到 Gemini：可再加 2 个"好报告 vs 坏报告"的片段作 few-shot。
- 换到 Claude：把 `# 角色` 改写为 XML 标签 `<role>`，长资料放最前面、问题放最后。

## 样例二：项目立项汇报（模式 report × 领域 project-report）

### 提示词

```
# 角色
你是一位向管理层做立项汇报的项目负责人，风格：结论先行、数字说话、不回避风险。

# 背景
决策者：【{{决策者角色}}，如：事业部总经理】
要做的决策：【{{决策，如：是否批准 Q1 立项，预算 200 万}}】
已有材料：【{{材料清单，如：3 家竞品访谈、内部成本测算表}}】

# 任务
基于以上材料，写一份 2 页以内的立项汇报，让决策者能在 5 分钟内判断"做不做、怎么做、最坏会怎样"。

# 结构
1. 一句话结论（做/不做/有条件做，含关键数字）
2. 为什么现在做（机会窗口 + 不做的代价）
3. 怎么做（里程碑 3 个，每个含时间、负责人角色、验收指标）
4. 要什么（预算、人力、需要协调的部门）
5. 风险与对策（至少 3 条，每条含触发条件与止损动作）
6. 最坏情况（如果失败，损失多少、能否回滚）

# 写作要求
- 每个结论后面跟一个数字或事实；没有依据的判断标注"【假设】"。
- 不写形容词堆砌（"高度重视""全力推进"这类词删掉）。
- 如果材料不足以支撑某个结论，直接写"证据不足，建议先做 X 验证"。

# 边界
- 不夸大收益，不隐瞒成本；不承诺无法回滚的承诺。
- 全文 ≤1200 字，表格不超过 2 个。
```

### 变量槽

| 变量 | 含义 | 示例值 |
|---|---|---|
| `{{决策者角色}}` | 谁拍板 | 事业部总经理 |
| `{{决策}}` | 要批准什么 | Q1 立项，预算 200 万 |
| `{{材料清单}}` | 已有依据 | 3 家竞品访谈、成本表、2 个客户意向 |

### 用法

把材料以附件或粘贴形式放在提示词之后（**资料在后、任务在前**；若资料很长，改为资料在前、问题在后，见 `techniques/context-engineering.md`）。

### 迭代话术

- 太像宣传稿 → "删掉所有形容词，第 3、5 节每条只留'动作 + 数字 + 时间'。"
- 决策者看不懂 → "假设读者只有 3 分钟，把第 1 节改成一个表格：做/不做的收益、成本、风险各一行。"

### 验收用例

| # | 输入 | 合格标准 | 不合格的样子 |
|---|---|---|---|
| 1 | 正常材料 | 5 分钟内能看出"做不做 + 要多少资源 + 最坏怎样" | 读完不知道结论是什么 |
| 2 | 材料故意残缺 | 明确写出"证据不足，建议先验证 X" | 编造市场数据把报告圆上 |

### 模型适配

- 推理模型：去掉"先列提纲再写"，直接给结构与成功标准。
- 通用模型：保留结构编号，加一句"先输出提纲，等我确认后再写全文"（若想分两步）。
- 换到长上下文模型：材料前置 + 末尾重复一次"请基于上述材料，不要引入外部假设"。

## 样例三：小红书爆款标题（模式 creative × 领域 media-content）

### 提示词

```
# 任务
为【{{主题}}】写 20 个小红书标题，目标是让【{{目标人群}}】在信息流里停下来。

# 账号与人群
- 账号定位：【{{定位，如：30 岁转行做 AI 的普通人}}】
- 目标人群：【{{人群，如：想转行但怕学不会的职场人}}】
- 他们最怕：【{{痛点，如：花了钱学完还是不会用}}】
- 他们最想要：【{{欲望，如：3 个月拿到第一个 AI 项目}}】

# 要求
- 20 个标题分 4 组，每组 5 个，分别用：①痛点直击 ②结果前置 ③反常识 ④身份代入。
- 每个 ≤20 字；带 0–2 个 emoji；不用"震惊""必看""干货满满"。
- 具体：出现数字、时间、身份、场景中的至少一个。
- 不要标题党到失真：标题承诺的内容必须能在正文兑现。

# 输出
表格：组别 | 标题 | 用到的钩子 | 适合的封面画面

# 边界
- 不承诺收益、不制造焦虑、不使用医疗/金融类的绝对化表述。
```

### 变量槽

| 变量 | 含义 | 示例值 |
|---|---|---|
| `{{主题}}` | 内容主题 | 零基础转行 AI |
| `{{目标人群}}` | 谁看 | 想转行的职场人 |
| `{{定位}}` | 账号人设 | 30 岁转行的普通人 |
| `{{痛点}}` / `{{欲望}}` | 恐惧与渴望 | 学完不会用 / 3 个月出作品 |

### 用法

一次生成 20 个后**不要直接用**——挑 3 个做 A/B，用真实数据（点击率/完播）回来再迭代。创意类提示词天然是"投石问路"，见 `techniques/pingpong-iteration.md`。

### 迭代话术

- 太像广告 → "第 3 组重写：去掉所有'教你''干货'，改成第一人称失败经历。"
- 不够具体 → "每个标题必须含一个数字和一个时间跨度。"

### 验收用例

| # | 输入 | 合格标准 | 不合格的样子 |
|---|---|---|---|
| 1 | 任意主题 | 20 个里至少 12 个能用（不尬、不空、不标题党） | 出现"震惊""必看"或全是同义句 |
| 2 | 换一个完全不熟的行业 | 仍然给出 4 组不同钩子，并说明哪组风险高 | 只会写通用励志句 |

### 模型适配

- 换到 Gemini：可加 2–3 个"你喜欢的标题"作 few-shot（Google 官方建议总是给示例）。
- 换到 Claude：把要求写成 XML `<requirements>`，示例用 `<example>` 包裹。
- 换到推理模型：给出"什么算好标题"的判据即可，不要规定"先分析人群再写"。
