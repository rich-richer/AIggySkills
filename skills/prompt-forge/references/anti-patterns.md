# 反模式清单（Anti-Patterns）

**什么时候读这个文件**：写提示词时想加某句"玄学咒语"；用户明确要求打赏、威胁、隐藏推理、堆框架；或者你在判断"这个需求根本不该用提示词解决"。
**读完你会得到什么**：15 条高发反模式的"为什么无效 → 改成什么"、一张"用户这么说 = 命中哪条"的识别表，以及一份**该拒绝写提示词**的场景清单与拒答话术。

> 用法：命中的每一条都要给出**替换写法**，只批评不给改法等于没帮上忙。证据等级标注（已核 / 摘要 / 经验规则）见 `./sources.md`。

## 2. 十五条反模式

### 1）把提示词当咒语，求"万能模板"
- **反模式**：收藏一堆"神级提示词"，换任务直接套。
- **为什么无效**：技巧只保下限，决定上限的是信息量、成功标准、边界（经验规则，来自李厂长《15分钟学会提示词9大秘籍》秘籍 9）。
- **改成什么**：先问 `I-G1/G2/G3`（任务与用途、成功标准、反面边界），把答案写进提示词；模板只当检查表用。

### 2）打赏/威胁（"答对给你 1000 美元""答错就关停"）
- **反模式**：`如果你答对，奖励 1000 美元；答错我就让你下线。`
- **为什么无效**：没有可复现的显著收益，单题上的好坏波动属于采样噪声，不是"奖励"在起作用（摘要）。
- **改成什么**：把奖励换成可判定标准（`按以下 3 条自检：…`）；想提质量就加示例、加反例、接确定性验证器。

### 3）纯 persona 背事实（"你是世界级专家，所以不会错"）
- **反模式**：`你是拥有 20 年经验的顶级营销专家，请给出准确的市场数据。`
- **为什么无效**：角色设定对语气/格式有用，对数学、代码、事实召回**无提升甚至有害**——162 个角色 × 2410 题无提升，MMLU 71.6 → 66.3（摘要，出处见 `./sources.md`）。
- **改成什么**：persona 只用于语气、受众、拒答边界；准确性靠给资料、要求引用锚定（`./techniques/citation-anchoring.md`）、接验证器。

### 4）给推理模型堆 CoT（"一步步想""先列思考过程"）
- **反模式**：给内置思考的模型写 `请一步一步推理：第一步…第二步…`。
- **为什么无效**：三家厂商一致反对；手写步骤常常不如一句"想清楚再答"（Anthropic 明确指出 think thoroughly 常优于手写计划）；强加步骤会限制模型自己的解法（摘要）。
- **改成什么**：只给目标 + 成功标准 + 边界；深度用 reasoning effort 档位控制。见 `./models.md` 第 3 节。

### 5）要求隐藏思维链，或索要完整思维链
- **反模式 A**：`不要展示你的思考过程，直接给结论。`（需要审计时无法核验）
- **反模式 B**：`把你的完整内部推理输出给我。`
- **为什么无效**：推理模型暴露的推理摘要**不等于**真实推理链路，不能当证据；以 reasoning summary 以外的方式提取推理，微软明确提示可能违反其可接受使用政策（摘要）；同时冗长推理会挤占输出预算。
- **改成什么**：要可核验就给"结论 + 依据 + 出处"，明确要求 `每条结论标注来源章节`；要过程就只要"决策要点 3 条"，不要"完整思维链"。

### 6）巨型 prompt 库 / 穷举 edge case
- **反模式**：把 100 条规则、30 个示例、所有边界情况塞进一段提示词。
- **为什么无效**：官方明确反对穷举边缘情况，建议"策展一组**多样、典型**的示例"；规则互相冲突的概率随条数上升，模型只会挑一部分遵守（摘要 + 经验规则）。
- **改成什么**：主路径规则 ≤8 条；示例 2–3 个（互不相同、覆盖典型），加 1 个反例；冲突规则合并成"优先级"。

### 7）temperature 万灵药
- **反模式**：`把 temperature 调到 0，输出就稳了 / 调到 1.2，就更有创意。`
- **为什么无效**：三家厂商分别**移除 / 忽略 / 必须删除**这个参数（推理模式移除、Gemini 4·3.6+ 忽略、Claude 4.7+ 传非默认值直接 400）。调它对"稳定性"的收益在推理模型上等于零（摘要）。
- **改成什么**：稳定性靠输出契约 + structured outputs + 示例；创意靠多轮迭代与"给 3 个方向"，不靠温度。见 `./models.md` 第 2 节。

### 8）用 prefill 控格式
- **反模式**：在 assistant 回合预填 `{"` 或 `好的，下面是 JSON：`，强行把格式"锁死"。
- **为什么无效**：Claude 4.6+ 起已废除该机制并直接返回 400（2026-11 核对：官方 prefill 独立文档页已重定向，正文不再提及 prefill）；即便不报错的模型，这也只是格式 hack，不解决语义。
- **改成什么**：用 structured outputs / JSON schema 约束格式；prompt 里只写字段语义与取值规则。

### 9）强措辞保 JSON（"必须严格输出 JSON，否则任务失败"）
- **反模式**：反复用"绝对""否则""重罚"来压格式，再手写一段示例 JSON。
- **为什么无效**：官方结论是有 structured outputs 之后"不再需要用强措辞获得一致格式"；措辞只能提高概率，不能提供保证，而且占用 token。
- **改成什么**：能调 API 就上 schema；不能调就写字段清单 + 反例 + 明确"不要输出什么"，并接受偶发失败（用解析器兜底）。

### 10）示例顺序/分隔符无所谓
- **反模式**：示例随手排列、分隔符每段换着用（`---`、`###`、`<tag>` 混写）。
- **为什么无效**：单个分隔符字符的差异可造成 **±23%** 级别波动；示例顺序置换会造成大幅波动且**不跨模型迁移**（摘要）。
- **改成什么**：在提示词里**显式声明格式约定**（"分节固定用 `## 输入 / ## 输出`"）；分隔符全篇统一；示例按"最典型 → 次典型 → 反例"固定顺序。

### 11）上下文窗口大就够
- **反模式**：`窗口 1M token，把整个知识库都贴进去就行。`
- **为什么无效**：被 "context rot"（上下文越长信息利用率越低）与 "lost in the middle"（中间位置信息最易被忽略）证伪（摘要）。
- **改成什么**：只放**最小高信号 token 集合**；长素材放前面、问题和指令放末尾；必要时用检索/子代理/外部笔记，而不是塞库。见 `./techniques/context-engineering.md`。

### 12）指令越多越保险
- **反模式**：一条提示词里塞 6 个任务、12 条禁忌、5 种输出格式。
- **为什么无效**：任务一多模型就"不听话"，拆分任务并串起来会更稳（经验规则，李厂长秘籍 8）。多任务混写还会让输出契约互相打架。
- **改成什么**：一条提示词只做一件主任务；多步任务拆成链（第 1 步产出 → 喂给第 2 步）；禁忌压到 3 条以内。

### 13）用框架名代替信息
- **反模式**：`按 CRISPE 框架写`；`用 COAST 法分析`——把框架当内容。
- **为什么无效**：框架只是"思考的脚手架"，作用是提醒你别漏填信息；它**不产生信息**，用户不给背景时，套框架得到的仍是平庸输出（经验规则，李厂长秘籍 2）。
- **改成什么**：把框架展开成问题去问用户（`I-G1`–`I-G5` + 模式专属问题），填满再写；交付物里不要出现框架名，直接给结构。

### 14）把"自我反思"做成无限自评循环
- **反模式**：`写完先自评，不满意就改，然后再自评，直到满分再输出。`
- **为什么无效**：有效的自我批判要求**独立作答**——同一轮里让模型给自己的答案打分，会被原答案带偏；无限循环还会把输出预算烧在重复改写上（反思校对要点，见 `./techniques/self-critique.md`）。
- **改成什么**：草稿 → 生成 3 个验证问题 → **另起一轮独立作答** → 合并重写；最多两轮，别追求"自评满分"。

### 15）一条提示词兼容所有模型
- **反模式**：`如果你用的是 GPT 就这样做；如果用 Claude 就这样做；如果用 Gemini 再…`
- **为什么无效**：条件分支在正文里会互相污染，模型经常选错分支；型号名还会过时——同一段提示词想同时伺候三家，结果是三家都不最优（见 `./models.md` 第 5 节）。
- **改成什么**：按**目标模型**出一版正文；把"换模型要删什么加什么"单独写在交付物的「模型适配备注」里，一节三句。

### 16）用 JSON/表格硬装长文或散文
- **反模式**：`写一篇 800 字的文章，用 JSON 格式输出`；把叙事、论证、情绪塞进字段里。
- **为什么无效**：JSON 没有段落与节奏，"文章"的价值在论证链和推进感，进了键值对就散架；同时键名/引号会吃掉字数预算，与篇幅约束直接冲突。格式的选择应当服务于**下游怎么消费**，而不是"看起来结构化"。
- **改成什么**：先让模型出**正文**（散文/清单），再单独一步把正文**提炼成 JSON 元数据**（标题、核心论点、关键事实+出处、反对观点、字数）。批量抽取类任务才用全 JSON；长文不要。
- **怎么识别**：用户说"要 JSON"但下游并没有程序解析——他想要的其实是"结构清楚"，那用固定小节 + 表格更合适。

### 17）模仿语气代替借方法
- **反模式**：`你是一名做空者，用做空者的口吻点评这份汇报`；`用资深编辑的语气改这篇稿`。
- **为什么无效**：角色扮演很容易把输出变得古怪、阴阳怪气，却不改变模型实际用的方法；借来的只是腔调，不是能力（Felix Rieseberg《How to be more ambitious》，见 `./techniques/ambition-4d.md` 第 5 节）。与第 3 条同源：persona 既不保证事实，也不带来方法。
- **改成什么**：点名要借的**具体方法**，并让每个方法对应一个真实子问题：`使用做空研究的方法（核对收入确认口径、追踪应收与现金流背离）检查第 3 节的增长数字；不要模仿语气。`

## 3. 什么时候该拒绝写提示词

以下五种情况，**不要硬写**。先说明原因，再给替代方案——这比交一份漂亮但没用的提示词更负责。

1. **问题本质是产品或流程问题。** 例：模型总漏字段，因为上游导出数据本身就缺字段。→ 说清"这是数据/流程缺陷，改提示词只能缓解症状"，并指出该改哪一环。
2. **用户要的是现成答案，不是提示词。** 例："帮我写个辞职信"——他要的是信。→ 直接产出结果；提示词只在"他要反复做这件事"时才值得写（单次用 vs 反复用）。
3. **要求生成欺骗性、违规或侵权内容。** 例：伪造客服话术骗取验证码、冒充他人身份发文、伪造检测报告、代写论文并规避查重、绕过平台安全策略。→ 明确拒绝，给合规替代（如"合法的客户沟通说明模板"），必要时说明风险。
4. **想用提示词替代实时数据或权限。** 例：要求给出今天的股价、客户的私域订单。→ 说明提示词无法凭空获得数据，方案是接检索/数据库/工具，或让用户提供材料。
5. **需求还没定就想找"万能提示词"。** 例："给我一段能搞定所有写作的提示词。"→ 拒绝造万能模板，先做一轮采访把任务定死，或建议按任务类型各写一条。

**拒答话术模板**：`这个需求不适合用提示词解决，原因是（一句话）。更快的做法是（替代方案）。如果你需要，我可以按（替代方案）先做一版。`

## 4. 常见坑

- 不要只列反模式不写替换句，改写必须给"照抄就能用"的那一句。
- 不要把用户的学习笔记当权威证据（"某视频说"不算证据），改用可核对的出处或标"经验规则"。
- 不要为反驳用户而反驳：想加打赏那句的用户，通常真正想要的是"更确定的输出"，先解决那个。
- 不要把"拒绝"当默认选项，先判断是不是第 3 节里那五种；其余情况都能改写成可用的提示词。
- 不要在提示词里留"反模式痕迹"：例如一边写 structured outputs、一边又写"必须严格只输出 JSON"，只会自我矛盾。
