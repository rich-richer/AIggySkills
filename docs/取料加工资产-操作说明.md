# 取料 → 加工 → 资产：操作说明

> 版本：2026-11-19 ｜ 适用：把网页/视频/书/文章或自己的经验，变成**可查、可做、可验收**的资产
> 配套 skill：`media-sourcing`（取料）、`distill-to-skill`（提炼）
> 核心原则：**别做"总结"，做"分级加工"；出口按用途选，不按材料选。**

---

## 0. 一句话记住

**能验收的做 skill，只能理解的做手册，要传播的做图文。**

---

## 1. 全景

```
① 取料         ② 结构          ③ 观点          ④ 岔路口        ⑤ 提炼         ⑥ 资产
media-sourcing → L1 只切不评 → L2 每条带出处 → 三个问题 → distill-to-skill → 出口
   integrity      骨架表         结论清单        选路线          判断规则        可复用
```

**纪律**：①只拿料 ②只切结构 ③只出结论 ④只做选择 ⑤只留可执行 ⑥只交成品。
每一步只做一件事——混着做，就会得到"什么都有一点、什么都不好用"的笔记。

---

## 1.5 每一级用什么做（工具映射）

| 级 | 动作 | 谁来做 | 类型 | 怎么触发 |
|---|---|---|---|---|
| **L0** 取料 | 拿可复核原文 | `media-sourcing` | skill | 「用 media-sourcing 把 X 取下来」 |
| | 先找来源 | `smart-search` | skill | 「帮我搜一下……」 |
| | 需登录的站 | `ego` 浏览器 + 你手动登录 | 内置工具 | 「打开这个页面，我登录」 |
| | 快速读单页 | `web_fetch` / `read_page` | 内置工具 | 直接给链接 |
| **L1** 结构 | 切 3–7 块骨架 | **无 skill** | **和 AI 对话** | 「只做结构，不做评价……」 |
| **L2** 观点 | 带出处的结论清单 | **无 skill** | **和 AI 对话** | 「在结构基础上，每部分提炼 1–2 条……」 |
| | 需外部核实 | `research` | skill | 「核实这条说法」 |
| **L3** 提炼 | 判断规则 + 三类分流 | `distill-to-skill` | skill | 「用 distill-to-skill 做成 skill」 |
| **L4** 资产 | 可加载 skill | `distill-to-skill` + `writing-for-agents` | skill | 同 L3 |
| | 学习手册 | `video-learning-handbook` | skill | 「做成学习手册」 |
| | 解说长文 | `deep-research-explainer` | skill | 「写成深度解说」 |
| | 图文/海报 | `infographic-builder` | skill | 「做成信息图」 |
| | 调研报告 | `research` | skill | 「调研并写成 md」 |
| | Word/PDF 排版 | `office-docx` | skill | 「导出 Word」 |
| | Obsidian 笔记 | **无 skill** | 直接写 md | 指定路径即可 |

### L1 / L2 就是"和 AI 对话"

这两级没有 skill，也不需要：**直接在对话里说那两句话就行**。

```
L1：只做结构，不做评价。把这份材料切成 3–7 个部分，每部分给出：
    1) 标题；2) 它回答的问题；3) 出现位置（时间戳/页码）。

L2：在结构基础上，每部分提炼 1–2 条结论。每条必须：
    1) 附原文位置；2) 标注 [作者明确说] 还是 [你的推断]。
```

唯一例外是**材料特别长**（一本书、2 小时播客）：

```
把材料按章/段分批交给 subagent，每个只输出该部分的结构表，最后合并成总表。
```

这是 `subagent` / `workflow` 的用法，只用于 L1 的分批，普通材料不要用。

### 为什么 L1/L2 故意留空

能力供给是倒金字塔：

```
L0 有 skill  ← 取料有无数坑（登录墙、403、0 字节、同音错字）
L1 无 skill  ← 只有一句话的纪律
L2 无 skill  ← 同上
L3 有 skill  ← 要可执行、可验收
```

**空缺不是遗漏，是省钱。** 每加一个 skill 就多一个触发词、多一份维护成本。
L1/L2 的问题从来不是"没有工具"，而是"人会跳过"——这靠约定，不靠工具。

## 2. 第①步：取料

**工具**：`media-sourcing`

**你要说**：

```
用 media-sourcing 把这个 <链接/文件> 取下来，给我原文和取料记录，不要总结。
```

**产出**：可复核文本 + 一份记录

```markdown
- source / type / method
- integrity: pass / degraded / fail
- coverage: 全文 / 第 1–3 章 / 00:00–06:17
- defects: 同音错字 / 登录墙 / 漏页 / 无
```

**判据（三查，缺一不算成功）**：

| 查 | 方法 | 失败信号 |
|---|---|---|
| 状态 | 日志 `Fetched (200)` | 403 / 404 / 429 |
| 体积 | `wc -c` | 0 字节或异常小 |
| 内容 | grep 目标关键词 | 只有登录/导航/页脚 |

**不合格怎么办**：

- `fail` → 换来源、让人提供，或放弃。**不许根据标题推测内容**。
- `degraded` → 可以用，但必须把缺口带进下一步，不能当下游不知道。

> ⚠️ 最常见的假成功：登录墙返回 200 + 32KB（全是扫码弹窗），或者 scrapling 403 + 0 字节却打印 "successfully saved"。

---

## 3. 第②步：结构（L1 · 只切不评）

**目标**：把材料切成 3–7 块骨架。**这一步不许出现任何观点。**

**可复制指令**：

```
只做结构，不做评价。把这份材料切成 3–7 个部分，每部分给出：
1) 标题；2) 它回答的问题；3) 出现位置（时间戳/页码）。
不要总结观点，不要提炼结论。
```

**产出长这样**（示范：一条 6 分钟视频）：

| # | 片段 | 它回答的问题 | 时间 |
|---|---|---|---|
| 1 | 命题：这件事是什么 | 和常见误解有什么不同？怎么判好坏？ | 00:00–00:34 |
| 2 | 路线一：从资料提炼 | 一份资料怎么变成能用的方法？ | 00:34–02:27 |
| 3 | 路线二：从经验沉淀 | 我做过的事怎么变成标准？ | 02:27–04:23 |
| 4 | 验证 | 怎么知道它真的可复用？ | 04:23–04:59 |
| 5 | 迭代 | "越用越好"靠什么机制？ | 04:59–05:36 |
| 6 | 落点 | 从哪件事开始？ | 05:36–06:16 |

**判据**：每一块都能用一句话说出"它回答什么问题"。说不出的，要么合并，要么删掉。

**常见错**：把"三条铁律""四步法"写进结构表——那是 L2 的事，提前做会污染骨架。

---

## 4. 第③步：观点（L2 · 每条带出处）

**可复制指令**：

```
在结构基础上，每部分提炼 1–2 条结论。每条必须：
1) 附原文位置；2) 标注 [作者明确说] 还是 [你的推断]。
不合并、不升华、不补充材料里没有的内容。
```

**产出长这样**：

| # | 结论 | 出处 | 性质 |
|---|---|---|---|
| 1 | 蒸馏是整理可读材料，不是训练模型 | 00:10–00:17 | [作者明确] |
| 2 | 判据是"下次能否用起来"，不是压缩多少字 | 00:17–00:24 | [作者明确] |
| 3 | 必须标源，否则会把 AI 补充当原文 | 01:30–01:44 | [作者明确] |
| 4 | 单次特殊要求不能写成通用规则 | 03:17–03:42 | [作者明确] |
| 5 | 改完要旧任务+新任务都检查 | 05:18–05:23 | [作者明确] |
| 6 | 元方法类内容，产物是"流程"不是"某条结论" | 02:14 + 06:07 | **[推断]** |

**判据**：

- 每条都能**指回原文位置**（时间戳、页码、段落）。
- `[推断]` 必须单独标出，不许混进作者原话。
- 一条结论都不能是"你应该……"——那是 L3。

**常见错**：把多个观点合并成一条漂亮话。合并即失真。

---

## 5. 第④步：岔路口（三个问题定出口）

依次问，答案是唯一路径：

| 序 | 问题 | 是 | 否 |
|---|---|---|---|
| 1 | 这份材料里有**可验收的动作**吗？（做完能被检查对错） | → 第⑤步 提炼 | → 问题 2 |
| 2 | 你要的是"看懂"还是"能做"？ | 看懂 → `video-learning-handbook`（可复习手册）或 `deep-research-explainer`（解说文） | → 问题 3 |
| 3 | 要给谁看？ | 给别人 → `infographic-builder` / 短文 | 只给自己 → Obsidian 笔记 |

**特例：元方法材料**（教"怎么做事的方法"的材料）

它提炼出来的是**流程**，不是业务结论。所以：

- 想固化这个流程 → 直接用它（往往等于 `distill-to-skill` 本身）
- 想用到业务上 → 走第⑤步，产出业务 skill

---

## 6. 第⑤步：提炼（L3 · 只留可执行）

**工具**：`distill-to-skill`

**你要说**：

```
用 distill-to-skill 把这份材料做成 skill：<粘贴 L1/L2 结果>
用途是 <谁> 在 <什么时机> 判断/完成 <什么动作>。
单次条件不要写成通用规则。
```

**先写目标句**（缺一项就别往下）：

```
我想用 [来源] 帮 [谁] 在 [时机] 判断/完成 [动作]，产出 [什么结果]。
```

**再写验收句**：`做到什么程度算合格？不合格长什么样？`

**产出**：三类分流表 + 判断规则 + 验收标准 + 示例

| 类别 | 判定 | 去向 |
|---|---|---|
| 每次都要检查的标准 | 无条件成立、可逐条核对 | 必查 |
| 视情况选择的做法 | 需要条件 | `IF … THEN … ELSE …` |
| 只属于这一次的信息 | 换对象不成立 | 示例（标注"换场景时怎么改"） |

**判据**：第三方能照着执行；每条规则有来源标记；单次条件全部降级为示例。

---

## 7. 第⑥步：出口（L4）

| 你想要的 | 用什么 | 验收方式 |
|---|---|---|
| 以后能**做** | `distill-to-skill` 产出 SKILL.md | 旧案例回归 + 新案例迁移 |
| 以后能**查** | `video-learning-handbook` 产出手册 | 复习卡能自测；术语表能查 |
| 现在能**懂** | `deep-research-explainer` | 没有技术背景也能复述 |
| 给别人**看** | `infographic-builder` / 短文 | 30 秒内看懂结论 |
| 放进笔记库 | Markdown（带 frontmatter） | 能被 grep 到、能双链 |

---

## 8. 时间预算

对一份 6 分钟视频 / 一篇长文：

```
取料 20% → 结构 15% → 观点 20% → 提炼 30% → 验证 15%
```

**异常信号**：如果你在"润色总结"上花了一半时间，说明你在给一个不该是终点的东西抛光。

---

## 9. 卡住了怎么办（回退表）

| 卡在哪 | 症状 | 说明什么 | 退回到 |
|---|---|---|---|
| ① 取料 | integrity = fail / 登录墙 | 来源不可得 | 换来源或人工提供，**不许猜** |
| ② 结构 | 切不出 3–7 块 | 材料太散或你缺背景 | 换材料，或先补背景再切 |
| ③ 观点 | 结论指不回原文 | 取料不完整 | 退回 ① |
| ④ 岔路口 | 两个都想要 | 目标不清 | 先写目标句，再选 |
| ⑤ 提炼 | 写不出验收标准 | 材料里没有方法，只有信息 | 改做手册，别硬做 skill |
| ⑤ 提炼 | 规则换场景就崩 | 单次条件混进通用区 | 重做三类分流 |
| ⑥ 验证 | 只有原案例通过 | 还没验证可复用 | 补一个新案例 |

## 10. 反模式清单

| 反模式 | 后果 |
|---|---|
| 取料后直接"帮我总结" | 得到要点清单，既查不到也做不了 |
| 总结和提炼混着做 | 规则模糊，无法验收 |
| 跳过结构直接提炼 | 提炼出的是模型常识，不是这份材料 |
| 没有出处 | 无法区分作者原话与 AI 补充 |
| 把单次条件写成永久规则 | 换个对象就误用 |
| 一个案例就宣布成功 | 假阳性，上线即失效 |
| 只验新案例不验旧案例 | 修好一处、弄坏一处 |
| 用"请注意"代替机制 | 软约束不可验证，等于没写 |
| 给每种加工都做一个 skill | 触发词打架、维护成本翻倍 |

---

## 11. 什么时候才加新 skill

**默认不加。** 满足任一再考虑：

1. 同一套模板用过 ≥3 次，且每次都犯同样的错（爱升华、丢出处、跳结构）；
2. 要团队共用一致标准，口头传不下去；
3. 要放进批处理/CI，需要机器可执行。

加的时候**合并而不是拆分**：L1+L2 合一个 `note-structuring`，不要做两个。

---

## 12. 一页速查卡

```
① 取料    media-sourcing → 查三样：状态/体积/内容
② 结构    对话：「只切不评」→ 3~7 块，每块"回答什么问题"
③ 观点    对话：「每条带出处」→ 标 [明确] / [推断]
④ 岔路    能验收？→ 看懂？→ 给谁看？
⑤ 提炼    distill-to-skill → 目标句 + 三类分流 + 双案例验证
⑥ 出口    skill / 手册 / 解说 / 图文 / 笔记
```

**三条底线**

1. 抓不到就说抓不到，不猜。
2. 没出处的规则不算规则。
3. 单次条件不进通用区。
